# 06 后续开发计划与构想

更新：2026-10-04。基于 [当前实现](03现有能力与实现对照.md)和 [缺口 ID](04待开发能力清单.md)。原始目标保持不变：有限领域、可持续、可核查、自主生成学习目标的研究智能体，不是自动聊天或普通 RAG。

## 1. 现在最优的推进方向

底层迁移、主张锚点、四结果争议、观察审计、预算、续跑和混合召回已经有实现，不应反复重写“基础模块”。下一步优先补 **内容级证据可靠性 + 认知审计**，随后建立 **可信评估与旧信念迁移审查**。这是把“能跑研究流程”提升为“结论为何可接受”的关键。

此前先推进功能并恢复离线基线；F01 A–D、F02、F03及F05只读最小范围现已接通，下一功能增量优先 **F04 高置信旧信念模型迁移盲审**；同时保持F01/F02/F03/F05实证关卡。测试和实验证明不能永久省略或无证据标记完成；未进行真实数据库或付费验收。

V01–V10 应在恢复测试阶段逐步作为上述交付关卡，不能等整套系统全部写完才第一次运行数据库。若用户继续暂缓，功能可增量开发，但状态始终写“已接通/待验收”。

新数据结构遵循：新增可空/默认字段或新表 → 迁移 → 保留旧记录未知状态 → 明确回填与数据量影响 → 备份/恢复检查。不要给旧 Claim 伪造“已经质量核验”，也不要批量删除旧认知追求表面干净。

## 3. 与初始构想相比，哪些保持、哪些偏差

| 初始构想 | 当前路线 | 剩余差距或选择 |
| --- | --- | --- |
| LLM 可替换，智能体身份独立 | 认知存在数据库；模型输出等级 0；比较不改旧信念 | 架构保持，模型真实版本/身份证据仍不完整 |
| L1 知识、L2 经验、L3 研究方法学习 | Claim/Belief/Evidence、会话反思、候选及验证 Skill | 参数级 L4 训练不在 V0.1；不能宣称模型权重学会了 |
| 工作/情景/语义/程序性四记忆 | 目标及会话上下文、会话历史、信念证据、方法文本 | 有对应存储角色，不是四套完整记忆控制系统 |
| 好奇心/缺口自主目标 | 种子、评分、反思后续目标、争议与复核目标 | 尚缺覆盖率/前置知识/掌握模型驱动的成熟 Curiosity Engine |
| 70% 聚焦、30% 探索 | exploration_rate 调节评分 | 不是严格配额；若恢复原策略，先定义统计周期和目标类型 |
| 固定每日学习/整合/评估时间 | run 有限循环，按日整合和里程碑检查 | 缺 OS 调度/常驻运营；不能把代码函数当每日服务 |
| Meta-memory / Mastery Profile | 近期分数、主题信念数、验证比例摘要 | 缺保持度、未覆盖知识和可靠掌握度模型 |
| 世界模型/知识图谱 | 来源支持边、目标父子边、来源依赖图 | 不是 requires/is_a/causes 等概念/因果图，需 F10 |
| 独立闭卷、迁移、保持和校准 | 动态闭卷模型观察；F03确定性真值协议、迁移/保持分区、Brier/Wilson与实际延时入口 | 评分已版本化；缺专家私有真值、语义独立/污染核查与真实多次延时实验 |
| 新模型质疑旧模型知识但不覆盖身份 | A1/A2/B1/B2 和四结果争议 | 缺高置信旧信念独立盲审，需 F04 |
| 外部模型盲审、批判、综合论证 | 浏览器适配/观察/规划建议 | 缺独立会诊和论证图；不能按模型数量增加证据票数 |
| 自动学习研究方法、改善效率 | 反思提取候选、独立题正增益后供规划使用 | 方法稳定泛化、负例和策略 A/B 未充分建立 |
| 30 天能证明成长 | 题集冻结、快照、里程碑及报告机制 | 尚无真实长期数据；“有测量代码”不等于“已证明提升” |
| 用户可直接开始 | 本地网页、文档导入、EXE 配方 | 增加便利入口不偏离核心，但正式安装/公网产品仍未完成 |

路线没有主动把项目缩减为聊天机器人，偏差主要在 **实现深度、实验可靠性和交付成熟度**。无法客观量化“偏差百分比”，也没有证据给出最终智能等级。

## 4. 完成功能且通过验收后能达到什么效果

预期你设置限定使命与预算后，系统能连续选题研究，积累可查原文的知识，对矛盾保持开放争议，围绕已学知识做闭卷/迁移/保持检查，发现缺口并复习，从成功/失败经验提炼研究方法，比较更换模型后的净效果，输出学习、费用和质量报告。你可以通过本地浏览器查看和干预，不必每一步手动聊天。

它仍会受网络、模型、来源、任务领域和预算限制，可能学不成功、判断错误或保留未解决。它不会凭空获得事实保证、无人机实体控制能力或无限自我进化。知识数量增长不是唯一成功标准。

## 5. 30 天实验必须怎样设计

1. 先固定领域、模型身份/版本、提示协议、预算、题集及评分公式。题目、答案和 rubric 不进入学习资料；划分研究题、迁移题、保持题，人工复查真值与重复样本。
2. 记录 Day 0 基线；Day 7/14/21/30 使用同一冻结版本并保留逐题回答、核验引用、记忆快照和费用。当前代码只记录实际运行的里程碑，不能补写不存在的历史成绩。
3. 同模型比较无记忆/有记忆，分开报告记忆增益与模型基础能力。模型替换再做 A1/A2/B1/B2，不把 B1 比 A1 的提升算成智能体学到的知识。
4. 技能用独立任务比较无方法/有方法，题目至少满足代码门槛 5 题，但样本数须由统计目的决定，不能把“5”当可靠泛化证明。
5. 多次运行报告波动和置信区间，人工抽查高置信错误、来源独立性和裁判偏差。允许报告无增益，归因泄漏、来源质量、模型漂移或策略失效。
6. 保持度用冻结旧知识题复测；F03入口强制实际间隔并重用原记忆快照，报告仅表示该快照辅助条件下的表现稳定性，不证明底层参数学会了。历史信念复核目标不等于标准化保持实验。校准只对有可靠评分的答案计算，unknown单列；动态闭卷裁判标签仍需真值校核。

初始稿中的“30 天提升 ≥20%、自主目标 >70%、verified >80%、高置信错误 <5%、至少 5 个技能、72 小时无人值守”是**目标假设，不是现有实测**。开始实验前明确 20% 是相对提升还是 20 个百分点、分母/样本、置信阈值、时间口径、人工介入和失败定义。禁止为了 verified 占比调低证据门槛。

## 6. 扩展构想与优先级边界

研究操作体验、证据图和可靠安装优先于公网多用户；认知有效性优先于更多模型适配；严格数据与证据优先于花哨仪表盘。背景索引、多代嵌入、关系图谱和多模型审查应各自以最小增量交付，不一次性另造框架。

真正的多用户/分布式队列、全自动策略优化、大规模跨域知识迁移、机器人仿真或实体任务属于后续项目范围，需独立设计、预算、权限与验收；不从当前“继续开发”默认推导出这些授权。
