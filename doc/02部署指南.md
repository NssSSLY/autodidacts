## 1. 部署形态与必需环境

| 形态 | 需要什么 | 适合什么 |
| --- | --- | --- |
| 本机 Python + 数据库容器 | Python 3.12+、Git、Docker Desktop、模型/网络配置 | 目前最直接的开发与体验方式 |
| 本机 Python + 原生/远程 PostgreSQL | Python 3.12+，支持 pgvector 的 PostgreSQL | 不希望本机装 Docker |
| 服务器源码运行 | Python、PostgreSQL+pgvector、进程管理、密钥及备份 | 持续学习；当前网页不是公网服务 |
| Windows 文件夹 EXE | 打包整目录、外部数据库、配置；浏览器模型另需 Chromium | 已有构建配方，未完成安装包验收 |

**不必部署服务器。** 当前 Docker Compose 只运行数据库，智能体在主机 Python 中运行，不是完整智能体容器部署。若模型通过 API 使用，本机无需 GPU；使用本地模型时硬件由模型推理服务决定，项目没有可信的最低内存/显存实测值。

项目要求 Python >=3.12；推荐先沿用已经有的 Python 3.12 环境。数据库示例是 PostgreSQL 16 + pgvector，SQLite 不能替代 JSONB、向量索引与 PostgreSQL 锁。Docker Desktop 的 Windows/WSL2/虚拟化条件按 [官方安装说明](https://docs.docker.com/desktop/setup/install/windows-install/)核对，不把 Docker 当成必须购买的服务器。

## 2. 创建项目 Python 环境

在 PowerShell 中：

```powershell
Set-Location C:\file\project\autodidact_v0_1
python --version
python -m pip --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

若 `python` 指向错误程序，可先用 `Get-Command python` 检查，或在安装了 Python Launcher 时改用 `py -3.12 -m venv .venv`。命令是 `python --version`（两个短横线），不是 `python -version`。

无需 Activate.ps1，因此不必修改全局执行策略。直接指定解释器即可使用虚拟环境；虚拟环境不适合从另一台电脑复制，应在目标机器重建。参见 [Python venv 官方说明](https://docs.python.org/3.12/library/venv.html)。

`pytest` 不是运行程序的必需依赖，也不需要往 Codex 内置 Python 安装。需要开发/测试时才安装：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
# 可选 PDF：
.\.venv\Scripts\python.exe -m pip install -e ".[documents]"
```

不要混用系统 pip、内置 Python 和项目解释器。本项目提供 scripts/dev_setup.ps1/sh 辅助脚本，但首次准备可按本节逐项执行，便于定位错误。

## 3. 数据库：先区分演示和安全部署

仓库 docker-compose.yml 当前使用演示账户 `autodidact/autodidact`，端口是 `5432:5432`，**不是仅回环绑定**。在共享电脑或网络环境部署前，手动调整：

- 端口映射改为 `127.0.0.1:5432:5432`，或取消主机映射，仅通过私有网络访问。
- 改用强密码，并同步 DATABASE_URL。不要把生产密码写入 Git；用未提交的部署配置或外部环境变量。
- 防火墙不开放公网 5432，日常业务账号避免使用数据库超级用户；迁移账号需有创建扩展/表/索引的权限。

完成配置后：

```powershell
docker compose up -d postgres
docker compose ps
docker compose exec postgres pg_isready -U autodidact -d autodidact
```

已有数据卷时，改 POSTGRES_PASSWORD 环境字段不会自动修改既有数据库账户密码；必须由管理员用数据库命令修改角色后同步连接配置。不要为了换密码删除卷。现有例子只是本机演示起点，不是生产安全配置。

不用 Docker 时安装 PostgreSQL 和 [pgvector 扩展](https://github.com/pgvector/pgvector)，建独立数据库与账号并配置 DATABASE_URL；扩展需在目标数据库可用。没有 pgvector 时，哪怕关闭嵌入也不能直接跳过当前数据库迁移。

## 4. 配置文件

保留已有配置，只在不存在时复制：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
notepad .env
```

最小运行配置为 DATABASE_URL 和 AGENT_CONFIG；mock 无模型密钥，但真实研究需真实提供方。模板：

```dotenv
DATABASE_URL=postgresql+asyncpg://autodidact:你的密码@127.0.0.1:5432/autodidact
AGENT_CONFIG=config/agent.yaml
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://你的兼容服务/v1
LLM_API_KEY=你的密钥
LLM_MODEL=提供方实际支持的模型名
SEARCH_PROVIDER=auto
```

密码中的 @、:、/、# 等需 URL 编码。仓库中的 .env.example 是字段清单；不应在截图或提交中暴露 .env。

| 配置 | 用途和注意事项 |
| --- | --- |
| LLM_PROVIDER | mock 演示，openai_compatible 真实 API/本地兼容服务 |
| LLM_BASE_URL / API_KEY / MODEL | 服务端地址、密钥、实际模型名；本地推理服务需另行启动 |
| JUDGE_LLM_MODEL / BASE_URL / API_KEY | 可选独立裁判；留空复用模型，但请求上下文仍隔离 |
| SEARCH_PROVIDER / BRAVE_SEARCH_API_KEY | auto 有 Brave 密钥时优先使用并降级；duckduckgo HTML 不是稳定 SLA |
| EMBEDDING_PROVIDER / BASE_URL / API_KEY / MODEL | 默认 disabled；启用 openai_compatible 时要求返回 1536 维 |
| LLM_MAX_OUTPUT_TOKENS | 默认 2048；长输出可能截断，也影响预留预算 |
| LLM_INPUT_USD_PER_MILLION / OUTPUT_USD_PER_MILLION | 按实际服务价格填写，0 是未知/未估算，不代表免费 |
| WEB_MODELS_CONFIG / ENABLED_WEB_MODELS | 外部网页模型配置路径及逗号分隔配置名；默认不启用 |
| BENCHMARK_SNAPSHOT_ID | 可选长期基准，填冻结后获得的 UUID；会追加调用 |
| MIGRATION_NEW_API_KEY | 比较另一服务模型的密钥；不通过命令行暴露 |

1536 是当前固定维度，不是任意模型可自动适配。切换嵌入后需要重建索引；来源、信念历史不会因重建改变。所有示例模型名称要向你使用的服务确认，文档不绑定具体型号。

config/agent.yaml 控制使命、来源数量、晋升门槛、重试、预算、安全和复核策略。首次体验可把每日调用/Token/搜索上限调小；`max_daily_estimated_cost_usd=0` 表示金额限制未启用。现有估算未覆盖全部搜索、订阅及嵌入费用，必须配合提供方控制台额度/告警。不要通过降低证据门槛掩盖配置失败。

## 6. 服务器运行与远程浏览器访问

源码可在服务器虚拟环境安装，使用该环境的 `python -m autodidact.cli` 同样初始化。DATABASE_URL 配置为受保护的数据库地址。当前没有一键 systemd/Windows 服务、完整应用容器镜像或公网多用户部署方案。

Linux 服务器的最小源码环境示例（先通过系统包管理准备 Python 3.12+、venv 与 PostgreSQL/pgvector；下面不安装系统服务）：

```bash
git clone https://github.com/NssSSLY/autodidacts.git
cd autodidacts
python3 -m venv .venv
.venv/bin/python -m pip install -e .
[ -f .env ] || cp .env.example .env
# 编辑 .env 与 config/agent.yaml，配置已准备好的数据库/模型后：
.venv/bin/python -m autodidact.cli init-db
.venv/bin/python -m autodidact.cli bootstrap
.venv/bin/python -m autodidact.cli run --max-cycles 5
# 需要网页时，另一个终端、相同配置目录运行：
.venv/bin/python -m autodidact.cli serve --port 8765
```

不要用管理员/root 权限运行学习器；服务配置与系统依赖由部署管理员准备。

持续运行需管理员配置进程管理和运行计划：设置工作目录、虚拟环境绝对路径、环境变量、日志轮换、备份和重启策略。`run --max-cycles` 到上限会正常退出，不能仅依赖“失败重启”策略维持学习。多进程不能当成分布式工作队列；当前只支持 PostgreSQL 控制器互斥。

工作台固定绑定服务器 127.0.0.1。若已有合法 SSH 访问权限，可通过本地隧道访问，而不暴露网页到公网：

```powershell
ssh -N -L 8765:127.0.0.1:8765 你的用户@你的服务器
```

服务器另行启动 `serve --port 8765`，本地浏览器访问 127.0.0.1:8765。隧道是单用户运维访问方式，不代替账号权限系统。不要简单修改监听地址或反向代理公开工作台。

## 7. Windows EXE 构建

F08 使用全新版本目录，不覆盖旧包；要求构建输入已经提交。先按第2节准备环境，显式允许安装可选打包/PDF依赖时运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_exe.ps1 -InstallDependencies
```

输出 `dist\releases\<UTC时间-Git短号-随机号>\package\Autodidact\Autodidact.exe`；**分发整个 package 目录**，其中包括 `Autodidact` 全目录、`RELEASE_MANIFEST.json`、`requirements-release.txt`。它包含 Python 运行组件/迁移/明确样例，不包含 PostgreSQL 服务/原生客户端、模型服务或 Chromium 浏览器安装/账户缓存。目标用户通常不再另装 Python，但仍需数据库/模型。不同操作系统需在对应平台构建，见 [PyInstaller说明](https://pyinstaller.org/en/stable/operating-mode.html)；资源清单在[spec机制](https://pyinstaller.org/en/stable/spec-files.html)中显式配置。

首次 EXE 启动在 `%LOCALAPPDATA%\Autodidact` 仅补缺失的 `.env`、`config/agent.yaml`、`config/run_plan.json` 和三个基准/盲审例子，不覆盖已有文件。无参数打开带计划预览的工作台，**不初始化数据库、不自动学习**。修改个人目录配置后，用实际新包路径替换下面变量：

```powershell
$autodidactExe = 'C:\你的发布目录\package\Autodidact\Autodidact.exe'
& $autodidactExe init-db
& $autodidactExe bootstrap

```

从任意位置调用冻结基准/导入文件时优先用绝对路径；EXE 改变工作目录到用户配置目录，源码 data 示例并非自动全部打包。外部网页模型 YAML/用户浏览器目录也需单独配置，不把浏览器登录资料或密钥打包给别人。

## 8. 备份、升级和恢复

先停止当前学习写入，记录代码版本、迁移版本、配置和模型/嵌入身份。配置和数据库分别安全备份（密钥不得进 Git）。以下针对未改名的示例 Compose 服务：

```powershell
New-Item -ItemType Directory -Path '.\backups' -Force
docker compose exec -T postgres pg_dump -U autodidact -d autodidact -Fc -f /tmp/autodidact-backup.dump
docker compose cp postgres:/tmp/autodidact-backup.dump .\backups\autodidact-backup.dump
```

## 9. 验证层级与常见问题

| 现象 | 先检查什么 |
| --- | --- |
| No module named pytest | 仅开发时安装 .[dev]，并使用同一个 .venv Python；运行程序不需要 pytest |
| No module named autodidact | 是否在项目根目录安装 -e .，当前解释器是否正确 |

| 模型/搜索失败 | 实际模型名、密钥、网络、服务限制；默认降级不代表高质量证据已经获得 |

### 9.1 F05 升级与验证

本轮没有新依赖、schema 或数据回填；已有 0008 库更新代码后重启 `serve` 并刷新网页即可。较旧库仍按第 8 节备份/停止写者后走既有迁移到 0008，不能为新界面跳过已有迁移。界面内置于 Python 模块，无 npm/前端构建步骤；EXE 应重新构建，但本轮没有 EXE 干净机器验证。
