## 总体结论

当前项目已经超过纯目录骨架阶段，具备可运行的最小学习循环和主要认识论数据结构，但仍处于 V0.1-alpha。已经实现的是“认知骨架与基础持久化”；尚未完成的是“严格证据质量、真正闭卷评估、长期记忆整合、模型迁移和网页模型完整接线”。

## 本轮完成的增量

### 1. Alembic 基线迁移

- `init-db` 不再依赖 `create_all`，而是升级到 Alembic 最新版本。
- 新数据库从空结构创建完整 V0.1 数据表。
- 旧版 `create_all` 数据库会先核对所有核心表和字段。
- 只有完全匹配基线时才无损标记迁移版本。
- 不完整或不一致的旧结构会停止自动迁移，避免损坏已有学习状态。

### 2. 搜索提供方抽象

- 引入统一 `SearchProvider`。
- 增加 Brave Search API 实现。
- 保留 DuckDuckGo HTML 无密钥后备。
- `auto` 模式在有 Brave 密钥时优先使用 API，否则使用后备。
- 主提供方失败或空结果时自动尝试下一提供方。
- 主学习器支持注入搜索实现，便于测试和后续路由。

### 3. 认识论安全与失败控制

- 存在未解决争议的主张不会晋升为信念。
- 没有可追溯来源的主张不会晋升。
- 单来源合格主张只能成为临时信念。
- 达到来源数量门槛且无争议的合格主张才可进入已验证状态；来源独立性仍需下一阶段增强。
- 争议历史记录真实的旧信念状态和置信度。
- 冲突主张会创建后续调查目标。
- 失败目标达到 `max_retry` 后转为 `BLOCKED`，不会无限占据目标队首。

## 下一批建议增量

1. 增加 `EmbeddingProvider` 与 pgvector 语义信念召回，替代“最近 40 条信念”比较。
2. 增加 URL 规范化、来源质量分类和来源血缘，避免把转载网页误算为独立证据。
3. 将评估拆成问题生成、闭卷回答、来源验证、迁移测试和校准评分。
4. 接通 `ModelObservation`，统一记录 API、本地和网页模型输出，默认证据等级为 0。
5. 为模拟 HTTP、LLM、数据库仓储和完整 `run-once` 增加端到端测试。
