## 本轮完成的增量

### 1. Alembic 基线迁移

- `init-db` 不再依赖 `create_all`，而是升级到 Alembic 最新版本。
- 新数据库从空结构创建完整 V0.1 数据表。
- 旧版 `create_all` 数据库会先核对所有核心表和字段。
- 只有完全匹配基线时才无损标记迁移版本。
- 不完整或不一致的旧结构会停止自动迁移，避免损坏已有学习状态。

### 2. 搜索提供方抽象

- 引入统一 `SearchProvider`。
- 增加 Brave Search API 实现。
- 保留 DuckDuckGo HTML 无密钥后备。
- `auto` 模式在有 Brave 密钥时优先使用 API，否则使用后备。
- 主提供方失败或空结果时自动尝试下一提供方。
- 主学习器支持注入搜索实现，便于测试和后续路由。

### 3. 认识论安全与失败控制

- 存在未解决争议的主张不会晋升为信念。
- 没有可追溯来源的主张不会晋升。
- 单来源合格主张只能成为临时信念。
- 达到来源数量、独立性和最低证据等级门槛且无争议的合格主张才可进入已验证状态。
- 争议历史记录真实的旧信念状态和置信度。
- 冲突主张会创建后续调查目标。
- 失败目标达到 `max_retry` 后转为 `BLOCKED`，不会无限占据目标队首。

### 4. 来源、目标与认识论链路加固

- 搜索结果只保留 HTTP(S)，移除跟踪参数和片段，并按规范 URL 去重。
- 网页重定向后的最终 URL、发布者键、质量类别、质量原因写入 `sources`。
- 同发布者或同正文哈希的来源合并为一个独立证据组。
- 普通网页默认 Level 1；模型输出保持 Level 0；预印本、学术/官方资料和标准按保守规则初筛，分类结果不等同于事实正确。
- `VERIFIED` 同时要求独立来源数量与最低证据等级；证据分数改由独立来源等级和可信度计算。
- 活动目标、同会话等价 Claim、重复 Evidence 和未结 Dispute 幂等复用。
- 等价主张再次通过评估时保留原 Belief 状态，并追加 `reobserved` 历史，不用新模型结论覆盖旧信念。
- Dispute 初始状态改为权威文档要求的 `unresolved`，且只有首次创建才写入争议历史和后续目标计数。
- 新增 Alembic `20260915_0002`，无损扩展来源元数据，并兼容未版本化的旧基线数据库。

- 新增 Alembic `20260920_0003`：以可逆、只扩展的方式增加 ClaimEvidence、争议决议元数据和部分唯一索引；旧记录不回填，保持兼容。
- Claim 只有在引用摘录逐字出现在已读取原文时才获得可用于晋升的来源 ID；失败锚点也保留审计记录。
- `DisputeResolver` 支持保留旧结论、采用新结论、条件化结论和保持未解决；前三者必须满足独立且已锚定的来源门槛。
- 新信念写入 1536 维嵌入；冲突前优先按 pgvector 余弦距离召回，嵌入提供方或数据库不可用时回退到最近信念。
