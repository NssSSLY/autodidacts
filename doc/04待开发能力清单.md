## 2. 已有代码，但必须补验收

这类任务不是“再写一套实现”。此前功能开发按用户要求暂缓测试。本轮注释维护按 AGENTS 运行已有离线 pytest，基线为 56 passed / 2 failed / 2 skipped；失败来自争议事务测试替身缺 scalars，属于 V01 待修复，不代表全部功能验收通过。在线数据库、故障注入和真实提供方验收仍未执行，后续用隔离测试库及可控替身开始，再做获授权的小额验证。

| ID | 需要的证据 | 风险 |
| --- | --- | --- |
| V01 | 先补齐争议事务测试会话接口的两项既有失败；完整 pytest/compileall、建立 CI | 当前基线 56 通过/2 失败/2 跳过，仍不能证明新链路全面可靠 |
| V02 | 0001–0005 在空库/旧状态副本升级，备份/新库恢复，记录行数与认知历史 | 幂等/迁移兼容性只靠静态看代码不足 |
| V03 | 高并发重复 Claim/Evidence/Dispute；四结果同事务与回滚 | 唯一索引和锁不能代替实际事务验证 |
| V04 | 每阶段故障注入，已保存输出复用，配置不兼容、人工 retry/restart | 检查重复调用费用、重复晋升、漏记结果 |
| V05 | DNS/重定向/内网地址/超大正文/恶意指令样本 | 检查安全读取及控制器不执行检索指令 |
| V06 | 共享 DOI、A→B→C、环、缺元信息、截断、普通引用样本 | 检查来源独立性不能被伪造地增加 |
| V07 | 中文/英文/矛盾主张标注查询；无向量/服务失败/指纹变化；大库召回 | 排序看似相关仍可能漏掉关键旧信念 |
| V08 | 作答请求确无原文/URL/rubric；核验失败和独立来源门控 | 检查闭卷和晋升不被模型自评分绕过 |
| V09 | 预算并发预留、进程中断、跨 UTC 日期、提供方 usage/账单差异 | 费用估算不是硬账单限制 |

| V12 | 真实模型/搜索/网页失败降级、小额端到端、长时间运行 | Mock 不能证明真实研究效果 |

验收报告记录代码提交、迁移、配置、数据集 hash、执行环境、结果、失败和未验证项；不能把跳过写成通过，也不能把付费验证偷偷夹在文档检查里。

## 3. 产品化尚未完成

目前存在原型入口，但不是正式多用户产品。未完成：公网认证授权、审计与数据隔离、长会话历史、成熟证据与争议界面、正式安装器/签名/更新机制、完整应用容器、运维告警和自动恢复服务。远程数据库与网页模型账户的运维权限仍由用户管理。

优先让单用户研究系统可审计、可恢复、可证明有效，再决定是否做公网、多用户或分布式部署；这些扩展需要新的范围、安全设计和授权。

## 4. 明确不应作为“补完功能”

- 训练/微调底层模型参数不是本项目 V0.1 的学习定义。
- CAPTCHA 绕过、反爬规避、凭据提取、无人值守支付、自主提权禁止实现。
- 任意 shell 执行、删除用户资料、自主修改核心代码不是默认学习权限。
- 新模型或网页意见不能直接替换高置信旧信念。
- 通用聊天界面和堆积资料不是研究学习效果的证明。

本项目的学习应体现为更可核查的认知、可迁移的研究方法和可复算的实验增益，而非能力列表长度。
