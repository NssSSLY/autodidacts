# 认知可靠性加固实施方案

更新时间：2026-09-24

## 目标与实施顺序

本轮优先保护已有学习状态，并让主张、证据、争议的状态变化可验证。按以下顺序实施；每一步通过对应验收后才进入下一步。

1. **迁移兼容与真实数据库验证。** 正确识别无 Alembic 版本的初始结构（0001）、来源元数据结构（0002）和当前结构（0003）；只在完整匹配时标记版本。既有记录不删除、不静默回填，迁移可回退。对空库、旧库和并发写入运行 PostgreSQL/pgvector 集成验证。
2. **争议决议一致性。** 四种结果都要留下完整历史。决议仅使用数据库中与相应结论关联且判为支持的来源，检查独立性和证据方向；信念、争议、历史与证据在一个事务中提交。重复提交应安全复用已有结果，未解决状态允许补充证据后重新决议。
3. **Claim 与原文的支持关系。** 原文摘录出现于网页只是“锚点有效”。再对“支持／反驳／条件支持／无法判断”做独立判定；只有“支持”且锚点有效的来源可以进入晋升门槛。模型判断只是带理由的观察，无法判断或提供方失败时保持待验证。
4. **验收与发布。** 运行定向测试、完整测试、编译和静态检查，记录真实 PostgreSQL 验证结果；更新实现状态文档，提交并推送远程仓库。

## 数据与兼容策略

- 旧 Claim、Evidence、Dispute 的现有行和主键均保留。无版本旧结构只有完全匹配已知版本才自动升级。
- 本轮复用 `claim_evidence.status` 和 `reason` 保存支持关系及理由，未增加字段或数据迁移；旧 `anchored` 记录保留，但不会被当作语义支持。重新评估后才更新对应记录及 Claim 可用来源。
- 旧程序仍可读取原有字段，但不能与新程序并行写入同一学习库：旧程序不会执行新的验证门槛。
- 数据库唯一约束是最终防线。非唯一约束错误应向上报告，不能被误当作重复写入。

## 验收标准

- 初始、来源元数据、当前三种结构均正确识别；缺表或未知字段组合拒绝自动标记。
- 引用原文真实但主张与原文相反、夸大范围或遗漏关键条件时，主张不因该来源晋升。
- 四种争议结果及其重试均有测试；部分失败不得留下半个决议。
- PostgreSQL/pgvector 环境可用时通过在线迁移、并发唯一约束和向量查询；环境不可用时报告未验证项，不把离线 SQL 测试称为在线通过。

## 本轮实施状态与运行门槛

- 已完成：修复无版本 0001/0002/0003 结构识别；只将完全匹配的旧结构标记并升级，保留已有记录。
- 已完成：Claim 先校验摘录锚点，再记录支持、反驳、条件支持或不明确的语义观察；只有已锚定且判为支持的来源进入晋升门槛。模型判断仍可能出错，应保留理由供复核，不能视为独立事实证明。
- 已完成：四种争议结果的数据库来源资格复查、独立性门槛、同事务写入与幂等重试；未解决状态可在补充证据后继续决议；`conditional` 只能采用已获支持且带条件的 Claim 原句。
- 已完成：精确识别 asyncpg 唯一约束冲突；其他完整性错误原样报告。离线单元测试覆盖事务失败、旧来源失效和异常分类。
- 待在线验收：当前开发环境没有可连接的 PostgreSQL/pgvector，因此在线迁移、并发唯一约束和向量查询测试尚未实际通过。

在线验收须使用名称以 `_test` 结尾的专用可丢弃 PostgreSQL 数据库，并允许创建 schema 和安装 pgvector 扩展。测试只清理自己创建的随机 schema，不碰生产库。设置 `AUTODIDACT_TEST_DATABASE_URL` 后运行：

```powershell
$env:AUTODIDACT_TEST_DATABASE_URL = "postgresql+asyncpg://用户:密码@主机:5432/autodidact_test"
.venv\Scripts\python.exe -m pytest -q tests/test_postgres_integration.py
```

未设置该变量时测试会跳过；跳过不代表在线验证通过。

## 后续阶段

完成本轮后，优先把评估拆成出题、闭卷回答、独立来源验证和校准评分，再接通自主争议调查队列。自主调查应产生受上述门槛约束的提案，不能直接改写旧信念。
