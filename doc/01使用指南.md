# 01 使用指南

更新：2026-10-03。安装准备见 [部署指南](02部署指南.md)，当前能力和限制见 [实现对照](03现有能力与实现对照.md)。下列命令在项目根目录的 PowerShell 中执行；示例均使用项目 Python，不依赖虚拟环境激活。

## 1. 它怎么工作

你给使命或学习目标，智能体按目标池优先级研究：规划 → 搜索/阅读 → 提取候选主张 → 检查原文支持与独立来源 → 对照旧信念/建立争议 → 闭卷评估并独立核源 → 谨慎晋升信念 → 反思、生成后续目标与记忆报告。

模型回答不会直接写成真相。来源不足、冲突未解决或评估失败时，保留候选、争议和失败记录是正常结果；信念数量为零不一定表示程序坏了。

## 2. 第一次开始

完成 02 的 Python、PostgreSQL、配置准备后：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli bootstrap
.\.venv\Scripts\python.exe -m autodidact.cli add-goal "理解无人机状态估计" --description "研究 IMU 与 GNSS 融合的基本假设、局限和证据"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
.\.venv\Scripts\python.exe -m autodidact.cli status
```

`bootstrap` 在目标库为空时建立初始目标，不会每次重复生成。新增目标进入队列，不保证下一轮就选到它；未完成的可恢复会话可能优先。不要给 `run-once` 添加问题参数，它没有这个参数。

默认 `LLM_PROVIDER=mock` 只适合检查程序路径，不是实际学习效果。真实学习需要配置可用模型和网络搜索。工作台和 CLI 共用同一个 DATABASE_URL 指向的持久学习库。

## 3. 浏览器网页操作

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli serve --port 8765
```

在浏览器打开 **http://127.0.0.1:8765**，不要用 localhost 替代（当前 Host 检查要求 127.0.0.1）。当前页面可以添加目标、触发/停止本进程学习、查看状态、围绕已接纳记忆提问。

这不是完整多轮聊天产品：回答以可接纳信念为基础，模型补充解释仍待核验，不直接改变信念。没有多用户账号、公网鉴权、完整证据图编辑或争议审批界面。终端 Ctrl+C 停止服务，不删除数据库；页面停止按钮不是删除学习记录。

普通浏览器查看工作台不需要安装 Playwright Chromium；只有调用外部网页模型适配器才需要它。不要同时在多个窗口启动学习任务。

## 4. 连续学习与成本

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli run --max-cycles 5
.\.venv\Scripts\python.exe -m autodidact.cli show-config
```

`run` 是有限轮次进程，不是已安装的 Windows 服务或每日定时任务。默认每进程最多 20 轮，轮间隔 30 秒；可通过 config/agent.yaml 调整。

每日预算包含模型调用、Token、搜索、网页读取、网页模型和嵌入调用。日期按 UTC 计（北京时间 08:00 换日）。先用小额度和单轮运行；重复试验、核源、争议调查会追加调用。金额预算是估算，不是提供方账单硬限额，详见 02。

## 5. 导入自己的材料

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli import-document "C:\资料\研究笔记.md"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

支持 UTF-8 TXT/Markdown；PDF 需安装 `.[documents]`。当前限制 20 MB、PDF 最多 100 页，不支持扫描件 OCR。导入会存来源和关联学习目标，不直接生成已验证信念；本地文档初始等级 1，不因“自己的文件”就自动可信。文件路径和提取文字会进入数据库，避免导入敏感资料。

## 6. 查找记忆、来源与争议

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "惯性导航 漂移" --kind all --limit 20
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "惯性导航" --kind belief --accepted-only
.\.venv\Scripts\python.exe -m autodidact.cli source-lineage "https://example.org/article"
.\.venv\Scripts\python.exe -m autodidact.cli queue-disputes
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

将 example URL 换成数据库里已有来源。检索可以返回 Goal、Claim、Belief；排序分数不是可信度，目标是意图，主张是候选，信念也要看状态与证据。未启用嵌入时走关键词/降级通道。

学习中发现高置信旧信念冲突会建争议并安排调查；`queue-disputes` 用于显式补排开放争议。调查可能保留旧结论、采用新结论、形成条件结论、保持未解决。无法找到足够独立证据时“不解决”也是合法结果，默认最多调查 3 次。

## 7. 中断与恢复

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli checkpoints --limit 20
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

新协议会复用已成功保存的搜索、读取、模型结构化输出等工作项；不是恢复模型内部思考或半次 HTTP 请求。外部调用完成但尚未入库就崩溃，仍可能重复调用并产生费用。

配置签名不兼容会出现 `resume_incompatible`。可恢复原模型、嵌入和学习策略后重试，或明确结束旧尝试，按新配置重开：

```powershell
# 将下面的 UUID 替换成 checkpoints 显示的 session_id
.\.venv\Scripts\python.exe -m autodidact.cli retry-session "实际会话UUID"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
# 仅在决定放弃原尝试、使用当前配置重开时执行：
.\.venv\Scripts\python.exe -m autodidact.cli restart-session "实际会话UUID"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

`retry-session` 清除续跑阻断并保留同一尝试，仍要求原配置；`restart-session` 结束旧尝试并重新排队，保留旧证据、工作项和预算账本。不要用删表、清库或改模型名来解决恢复问题。早期无续跑协议会话不能自动获得历史工作项缓存。

## 8. 重建派生索引

升级旧库、切换嵌入模型或排查召回缺失时：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-lineage --limit 200
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-retrieval --limit 200
# 已配置兼容的 1536 维嵌入服务时才执行：
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-retrieval --limit 200 --vectors
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-embeddings --limit 100
```

按批次重复直到无剩余更新。`rebuild-lineage` 只回填已存 metadata，不重新下载或猜测缺失关系；`rebuild-retrieval` 覆盖三类实体派生索引；`rebuild-embeddings` 是旧 Belief 向量维护入口。嵌入指纹不匹配的旧向量不会跨模型直接比较。派生索引不是认知事实，不要把重建当成重新验证信念。

### 8.1 查看主张范围与原文审计（F01）

完成 0006 升级后，新提取的 Claim 可记录 scope.conditions（适用条件）、time_scope（时间范围）、units（单位）。这些仍是提议；限制也必须出现在主张正文，避免检索、冲突比较或作答时被遗漏。例如：“2025年在低照度条件下，速度误差为0.2 m/s”，不能保存成无条件的“误差为0.2”。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "低照度" --kind claim
# 从上一步 hits 中取实际 id：
.\.venv\Scripts\python.exe -m autodidact.cli show-claim "实际主张UUID" --limit 20
```

输出 scope、有库内来源关联的引文之来源/原文/status/reason，以及 assessment 中的范围覆盖、原文上下文/hash、模型身份、协议和失败原因。最多显示指定数量，truncated 表示仍有未显示记录。没有读到的来源不能生成关联证据，原候选引文仍保留在学习结果中。该命令不调用模型或开展研究，但沿用 CLI 初始化流程，使用前应备份并完成迁移。

有显式范围的支持观察必须 scope_coverage=complete，且符合已存主张范围；incomplete 留 conditional，unknown/失败留 unclear，不能供晋升。旧记录 scope/assessment 为空表示未知，不等于永远有效；模型覆盖观察并不保证原文真实。单位换算、同义范围仍不自动推断。

核验协议现为 claim_scope_v1，加入续跑签名。升级前尚未结束的会话可能返回 resume_incompatible；保留旧会话并人工 restart-session 创建新尝试（见第 7 节），不能用 retry-session 绕过协议差异。已完成会话和旧证据不清除。

### 8.2 作者、发布日期、研究标识与质量理由（F01-B/D）

完成 0007 升级后，新读取网页会从明确的 meta/文章 JSON-LD 提取作者、发布日期、DOI/arXiv/PMID；普通参考文献中的 DOI 不冒充本页身份。来源 ID 可从 show-claim 的 evidence 中取得：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli show-source "实际来源UUID"
```

输出 bibliography（值、原始声明、meta/jsonld 出处）、同正文 URL 的有界首次观察、quality_audit（正文 hash、方法/结果/引文/局限/撤稿等信号位置和分类理由），以及当前 effective_quality。书目不是身份认证；日期冲突、年份/月度、不合法值保持未知，日历日期的数据库 UTC 零点不是已知出版时刻。本地 TXT/MD/PDF 暂不猜测作者/出版日期，也不做 DOI/Crossref 在线认证。

质量与晋升分开：URL/书目单独不足以提高质量；摘要/缺少正文信号通常最高1，参考型文章最高2，完整结构研究或规范文档最高3；不自动授予已复现/证明等级4–5。模型、明确撤稿信号为0，不能供事实晋升。正文规则可能误判，仍需要逐引文支持、独立性和评估门控。

旧记录不自动联网回填或改写信念。旧来源在新晋升/决议中重新计算正文等级上限，只降不升；重读同URL可补未知书目，同正文镜像不能覆盖原作者/日期或提高旧等级。stored quality_audit 是读取时观察，effective_quality 是当前门控结果。两条 show 命令不调用外部服务，但 CLI 会先初始化迁移，需先备份/停写。

### 8.3 复合主张分别核验（F01-C）

例如“2024年低照度时，甲误差2m且乙速度3m/s”，先保留原父句，模型提出至多8个子句并另次复核等价/原子性/范围/无新增事实。共同条件和时间保守继承，单位按文字映射到各子句；隐式条件是否丢失仍依赖模型复核，不保证完美拆分。

show-claim 的 structure 显示父/子 ID、拆分提议、复核和失败理由。原子子句继承候选引文，但每句分别定位原文、核对支持和范围；只有甲的引文不能让乙或整个父句晋升。复合/不确定父句不直接晋升或被采用为新决议，争议可以保持未解决或选择有足够证据的条件子句。调查子句属于实际调查会话，不借旧会话身份。search-memory 也返回 claim_structure。

首次结构观察保留，重复提取不覆写门控；失败候选可在新的学习尝试重新提出，不批量拆旧主张。atomic_claim_v1、bibliography_declared_v1、content_quality_v1 都加入续跑签名。每个新候选通常增加拆分及复核两次模型请求（不确定/早期拒绝只一次），随后还有逐子句核证；沿用既有预算和缓存，无新增环境变量。模型失败保留候选而不放行；预算耗尽交上层暂停。

## 9. 记忆、技能、报告

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli consolidate
.\.venv\Scripts\python.exe -m autodidact.cli skills
.\.venv\Scripts\python.exe -m autodidact.cli refresh-profiles
.\.venv\Scripts\python.exe -m autodidact.cli report --days 30
.\.venv\Scripts\python.exe -m autodidact.cli show-report "实际报告UUID"
```

每日整合按 UTC 日期幂等，生成记忆/证据图摘要、失败模式、复核目标和候选技能，不是自动删除旧知识。至少 3 次有经验总结的成功会话后才尝试提取方法；候选技能未验证前不能当成有效提升。ModelProfile 是观测统计，不是经严格实验校准的模型信誉。

## 10. 基准、技能验证和模型比较

以下操作会调用模型，不属于首次安装的必做步骤：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli freeze-benchmark --path data/benchmark/sample.json
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark "实际基准UUID"
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark "实际基准UUID" --use-memory
.\.venv\Scripts\python.exe -m autodidact.cli validate-skill "实际技能UUID" "实际基准UUID"
.\.venv\Scripts\python.exe -m autodidact.cli compare-models "实际基准UUID" "旧模型名称" "新模型名称"
```

自定义题集是 JSON 数组，每题需 `question`，并有 `rubric` 或 `accepted_answers`。样例只有 2 题，仅演示流程；技能验证代码要求至少 5 题，并排除与技能提取目标题面完全相同的题；不会自动检测题集内部重复或保证语义独立，独立任务应由你另行准备和核查。精确答案匹配和模型裁判都有限制，不能用小样例一次涨分宣称“智能提升”。

比较会保存 A1 旧模型无记忆、A2 旧模型有记忆、B1 新模型无记忆、B2 新模型有记忆四组；不会自动切换模型或覆盖旧信念。跨服务可用 `--new-base-url`，新密钥放 `MIGRATION_NEW_API_KEY`，不放命令行。

设置 `BENCHMARK_SNAPSHOT_ID` 可在学习过程触发 Day 0/7/14/21/30 检查；需要进程在相应日期运行，未运行的历史里程碑不会补造。完整实验设计见 [06](06后续开发计划与构想.md)。

## 11. 外部网页模型（可选）

经服务条款和账户权限允许后，复制 config/web_models.example.yaml 到 config/web_models.yaml，为实际网站配置选择器及独立浏览器资料目录，设置 ENABLED_WEB_MODELS。用户手动登录，不绕过验证或反爬。

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m autodidact.cli web-ask "实际配置名" "请提出该研究问题需要核查的假设"
```

输出只作为等级 0 观察；引用网页仍要独立读取核查。现有接入不等于原构想的完整盲答、交叉质疑、综合论证流程。

## 12. 判断是否真正可用

先检查服务能启动和状态能持久保存，再核对一次真实目标的来源原文、主张引文、争议状态、评估核验引用和报告。重启后数据应仍存在。缺少密钥、网络失败或来源不足要解释为配置/证据问题，不应靠降低可信门槛强行“学习成功”。

本轮只运行离线回归（121 passed / 3 skipped）、编译和静态检查，未代你运行真实学习、数据库升级或付费调用。真实验收按 [04 的验收清单](04待开发能力清单.md)执行。
