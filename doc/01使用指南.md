# 01 使用指南

更新：2026-10-20。安装准备见 [部署指南](02部署指南.md)，当前能力和限制见 [实现对照](03现有能力与实现对照.md)。下列命令在项目根目录的 PowerShell 中执行；示例均使用项目 Python，不依赖虚拟环境激活。

## 1. 它怎么工作

你给使命或学习目标，智能体按目标池优先级研究：规划 → 搜索/阅读 → 提取候选主张 → 检查原文支持与独立来源 → 对照旧信念/建立争议 → 闭卷评估并独立核源 → 谨慎晋升信念 → 反思、生成后续目标与记忆报告。

模型回答不会直接写成真相。来源不足、冲突未解决或评估失败时，保留候选、争议和失败记录是正常结果；信念数量为零不一定表示程序坏了。

## 2. 第一次开始

完成 02 的 Python、PostgreSQL、配置准备后：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli bootstrap
.\.venv\Scripts\python.exe -m autodidact.cli add-goal "理解无人机状态估计" --description "研究 IMU 与 GNSS 融合的基本假设、局限和证据"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
.\.venv\Scripts\python.exe -m autodidact.cli status
```

`bootstrap` 在目标库为空时建立初始目标，不会每次重复生成。新增目标进入队列，不保证下一轮就选到它；未完成的可恢复会话可能优先。不要给 `run-once` 添加问题参数，它没有这个参数。

默认 `LLM_PROVIDER=mock` 只适合检查程序路径，不是实际学习效果。真实学习需要配置可用模型和网络搜索。工作台和 CLI 共用同一个 DATABASE_URL 指向的持久学习库。

## 3. 浏览器网页操作

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli serve --port 8765
```

在浏览器打开 **http://127.0.0.1:8765**，不要用 localhost 替代（当前 Host 检查要求 127.0.0.1）。当前页面可以添加目标、触发/停止本进程学习、查看状态、围绕已接纳记忆提问。

这不是完整多轮聊天产品：回答以可接纳信念为基础，模型补充解释仍待核验，不直接改变信念。没有多用户账号、公网鉴权、完整证据图编辑或争议审批界面。终端 Ctrl+C 停止服务，不删除数据库；页面停止按钮不是删除学习记录。

普通浏览器查看工作台不需要安装 Playwright Chromium；只有调用外部网页模型适配器才需要它。不要同时在多个窗口启动学习任务。

### 3.1 认知审计（F05，只读）

同一页面向下找到“认知审计 · 只读”，无需另外启动服务。先选信念、主张、来源、争议、报告或预算事件，填写可选关键词，点击“查询 / 刷新列表”；每页可选 10/20/50 条并翻页。空库显示“暂无匹配记录”，不是学习失败。

- 点击“查看信念”：查看当前状态/评分、支持/反对/条件 Evidence、scope、复核尝试；切换“信念历史”看变更前后状态及理由，或看相关争议/复核报告。撤回信念不会被隐藏。
- 沿“核验原主张 / 晋升主张”进入 Claim：看原结论、范围、拆分父子结构、逐引文状态、原文与核验理由；再沿“引文来源”查看 Source。
- Source 显示书目声明/出处、存储质量审计和当前有效质量上限；“保存原文”每次读 12000 字符，“来源血缘”显示相邻依赖边及已入库关联。普通 cites 不自动合并独立性；未知或未入库目标不会自动抓取。
- Dispute 可看旧信念快照、新主张、调查/决议理由及四结果：keep_old 保留旧、adopt_new 采用新、conditional 条件化、unresolved 保持未解决。没有记录显示未知，不伪造已决议。
- 预算事件列表另显示 UTC 今日已知实耗/未知预留与配置上限；actual 空表示未知、0 表示真实零。金额是估算而非账单硬限额，未设上限不表示免费。

关联按钮仅在库内追溯；“返回上一条详情”最多保留 20 步浏览路径。列表不自动刷新，学习产生新记录后手动查询。关键词是字面文本搜索，不是语义检索；状态框精确匹配：信念/争议/预算为 status，来源为 quality_class，报告为 kind，主张为 topic。例如 `retracted`、`resolved`、`belief_review`，不确定时留空。

审计不调用模型/搜索/嵌入，不重新核验、修改置信度、撤回信念或提交决议。不要把它与页面原有“学习 / 提问 / 创建目标”混淆，后者仍可能写状态或计费。JSON/原文均按纯文本展示，不执行内含 HTML/指令。空范围/书目/历史是未知，不是已核验；达到展示/分页上限会提示，不声称已看全证据。

行偏移最高 10000，原文偏移最高 2000000；深层/大正文展示会截断，数据库原值不变。每次读取有独立一致性只读快照，但不同页不是冻结数据集，学习并发新增时可有重复/位移；大库全量导出不是此功能。直接 API 为 `GET /api/audit/{sources|claims|beliefs|disputes|reports|operations}` 及 `/{UUID}` 详情，必须携带页面访问 Token，不支持 POST。

## 4. 连续学习与成本

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli run --max-cycles 5
.\.venv\Scripts\python.exe -m autodidact.cli show-config
```

`run` 是有限轮次进程，不是已安装的 Windows 服务或每日定时任务。默认每进程最多 20 轮，轮间隔 30 秒；可通过 config/agent.yaml 调整。

每日预算包含模型调用、Token、搜索、网页读取、网页模型和嵌入调用。日期按 UTC 计（北京时间 08:00 换日）。先用小额度和单轮运行；重复试验、核源、争议调查会追加调用。金额预算是估算，不是提供方账单硬限额，详见 02。

## 5. 导入自己的材料

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli import-document "C:\资料\研究笔记.md"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

支持 UTF-8 TXT/Markdown；PDF 需安装 `.[documents]`。当前限制 20 MB、PDF 最多 100 页，不支持扫描件 OCR。导入会存来源和关联学习目标，不直接生成已验证信念；本地文档初始等级 1，不因“自己的文件”就自动可信。文件路径和提取文字会进入数据库，避免导入敏感资料。

## 6. 查找记忆、来源与争议

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "惯性导航 漂移" --kind all --limit 20
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "惯性导航" --kind belief --accepted-only
.\.venv\Scripts\python.exe -m autodidact.cli source-lineage "https://example.org/article"
.\.venv\Scripts\python.exe -m autodidact.cli queue-disputes
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

将 example URL 换成数据库里已有来源。检索可以返回 Goal、Claim、Belief；排序分数不是可信度，目标是意图，主张是候选，信念也要看状态与证据。未启用嵌入时走关键词/降级通道。

学习中发现高置信旧信念冲突会建争议并安排调查；`queue-disputes` 用于显式补排开放争议。调查可能保留旧结论、采用新结论、形成条件结论、保持未解决。无法找到足够独立证据时“不解决”也是合法结果，默认最多调查 3 次。

## 7. 中断与恢复

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli checkpoints --limit 20
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

新协议会复用已成功保存的搜索、读取、模型结构化输出等工作项；不是恢复模型内部思考或半次 HTTP 请求。外部调用完成但尚未入库就崩溃，仍可能重复调用并产生费用。

配置签名不兼容会出现 `resume_incompatible`。可恢复原模型、嵌入和学习策略后重试，或明确结束旧尝试，按新配置重开：

```powershell
# 将下面的 UUID 替换成 checkpoints 显示的 session_id
.\.venv\Scripts\python.exe -m autodidact.cli retry-session "实际会话UUID"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
# 仅在决定放弃原尝试、使用当前配置重开时执行：
.\.venv\Scripts\python.exe -m autodidact.cli restart-session "实际会话UUID"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
```

`retry-session` 清除续跑阻断并保留同一尝试，仍要求原配置；`restart-session` 结束旧尝试并重新排队，保留旧证据、工作项和预算账本。不要用删表、清库或改模型名来解决恢复问题。早期无续跑协议会话不能自动获得历史工作项缓存。

## 8. 重建派生索引

升级旧库、切换嵌入模型或排查召回缺失时：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-lineage --limit 200
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-retrieval --limit 200
# 已配置兼容的 1536 维嵌入服务时才执行：
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-retrieval --limit 200 --vectors
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-embeddings --limit 100
```

按批次重复直到无剩余更新。`rebuild-lineage` 只回填已存 metadata，不重新下载或猜测缺失关系；`rebuild-retrieval` 覆盖三类实体派生索引；`rebuild-embeddings` 是旧 Belief 向量维护入口。嵌入指纹不匹配的旧向量不会跨模型直接比较。派生索引不是认知事实，不要把重建当成重新验证信念。

### 8.1 查看主张范围与原文审计（F01）

完成 0006 升级后，新提取的 Claim 可记录 scope.conditions（适用条件）、time_scope（时间范围）、units（单位）。这些仍是提议；限制也必须出现在主张正文，避免检索、冲突比较或作答时被遗漏。例如：“2025年在低照度条件下，速度误差为0.2 m/s”，不能保存成无条件的“误差为0.2”。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli search-memory "低照度" --kind claim
# 从上一步 hits 中取实际 id：
.\.venv\Scripts\python.exe -m autodidact.cli show-claim "实际主张UUID" --limit 20
```

输出 scope、有库内来源关联的引文之来源/原文/status/reason，以及 assessment 中的范围覆盖、原文上下文/hash、模型身份、协议和失败原因。最多显示指定数量，truncated 表示仍有未显示记录。没有读到的来源不能生成关联证据，原候选引文仍保留在学习结果中。该命令不调用模型或开展研究，但沿用 CLI 初始化流程，使用前应备份并完成迁移。

有显式范围的支持观察必须 scope_coverage=complete，且符合已存主张范围；incomplete 留 conditional，unknown/失败留 unclear，不能供晋升。旧记录 scope/assessment 为空表示未知，不等于永远有效；模型覆盖观察并不保证原文真实。单位换算、同义范围仍不自动推断。

核验协议现为 claim_scope_v2，加入续跑签名。有显式范围的反对/条件观察也须确认与原条件/时间/单位相容，否则 unclear；不能拿不同时期或不相交人群当反例。升级前尚未结束的会话可能返回 resume_incompatible；保留旧会话并人工 restart-session 创建新尝试（见第 7 节），不能用 retry-session 绕过协议差异。已完成会话和旧证据不清除。

### 8.2 作者、发布日期、研究标识与质量理由（F01-B/D）

完成 0007 升级后，新读取网页会从明确的 meta/文章 JSON-LD 提取作者、发布日期、DOI/arXiv/PMID；普通参考文献中的 DOI 不冒充本页身份。来源 ID 可从 show-claim 的 evidence 中取得：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli show-source "实际来源UUID"
```

输出 bibliography（值、原始声明、meta/jsonld 出处）、同正文 URL 的有界首次观察、quality_audit（正文 hash、方法/结果/引文/局限/撤稿等信号位置和分类理由），以及当前 effective_quality。书目不是身份认证；日期冲突、年份/月度、不合法值保持未知，日历日期的数据库 UTC 零点不是已知出版时刻。本地 TXT/MD/PDF 暂不猜测作者/出版日期，也不做 DOI/Crossref 在线认证。

质量与晋升分开：URL/书目单独不足以提高质量；摘要/缺少正文信号通常最高1，参考型文章最高2，完整结构研究或规范文档最高3；不自动授予已复现/证明等级4–5。模型、明确撤稿信号为0，不能供事实晋升。正文规则可能误判，仍需要逐引文支持、独立性和评估门控。

旧记录不自动联网回填或改写信念。旧来源在新晋升/决议中重新计算正文等级上限，只降不升；重读同URL可补未知书目，同正文镜像不能覆盖原作者/日期或提高旧等级。stored quality_audit 是读取时观察，effective_quality 是当前门控结果。两条 show 命令不调用外部服务，但 CLI 会先初始化迁移，需先备份/停写。

### 8.3 复合主张分别核验（F01-C）

例如“2024年低照度时，甲误差2m且乙速度3m/s”，先保留原父句，模型提出至多8个子句并另次复核等价/原子性/范围/无新增事实。共同条件和时间保守继承，单位按文字映射到各子句；隐式条件是否丢失仍依赖模型复核，不保证完美拆分。

show-claim 的 structure 显示父/子 ID、拆分提议、复核和失败理由。原子子句继承候选引文，但每句分别定位原文、核对支持和范围；只有甲的引文不能让乙或整个父句晋升。复合/不确定父句不直接晋升或被采用为新决议，争议可以保持未解决或选择有足够证据的条件子句。调查子句属于实际调查会话，不借旧会话身份。search-memory 也返回 claim_structure。

首次结构观察保留，重复提取不覆写门控；失败候选可在新的学习尝试重新提出，不批量拆旧主张。atomic_claim_v1、bibliography_declared_v1、content_quality_v1 都加入续跑签名。每个新候选通常增加拆分及复核两次模型请求（不确定/早期拒绝只一次），随后还有逐子句核证；沿用既有预算和缓存，无新增环境变量。模型失败保留候选而不放行；预算耗尽交上层暂停。

### 8.4 负面证据与历史信念复核（F02）

先停写、备份并执行 init-db 升级到当前HEAD0009（F02由0008引入）。随后可排队过旧信念，或指定一个信念：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli queue-belief-reviews --limit 3
.\.venv\Scripts\python.exe -m autodidact.cli queue-belief-reviews --belief-id "实际信念UUID"
# run-once执行目标池中优先级最高的任务，不保证立刻选中上述目标；可能调用真实搜索/模型并计费。
.\.venv\Scripts\python.exe -m autodidact.cli run-once
.\.venv\Scripts\python.exe -m autodidact.cli show-belief "实际信念UUID" --limit 50
```

show-belief展示原结论/范围、support（支持）/attack（反对）/context（条件）原文、ClaimEvidence关联及核验快照；latest_review是最近取得合格观察的复核，latest_review_attempt还显示unknown/needs_follow_up失败尝试和报告ID，可继续show-report。显示观察成功不代表原结论判真或保持测试通过。旧Evidence的新关联为空、assessment为空意味着未知。

普通学习有界复核至多10个相关旧信念；反对/条件原文或旧支持来源等级下降触发复核目标。每日整合/目标池为空时扫描最旧100条候选，默认排至多3条超过memory_review_days的信念；仅排队，不修改置信度。年龄/撤稿线索是调查理由，不能直接判错。队列遵守每日目标额度；同周期同原文线索复用目标，新原文线索可另建目标，blocked不循环重建绕过重试上限。

专门复核排除旧支持来源的URL/正文/出版方/已知依赖，再读独立来源并核验原结论原范围。反对/条件观察之外还需有正等级原文支持的原子替代句，才可开争议并排独立调查；之后仍由既有四结果Resolver处理。没有合格替代句留needs_follow_up，未读到资料/模型失败留unknown，按max_retry有界重试，不静默撤回或降低旧评分。没有来源不等于没有反例。

belief_review_v1和claim_scope_v2加入续跑签名；旧进行中尝试须人工restart而非修改签名冒充兼容。沿用现有搜索/模型预算及成功工作项缓存，无新增密钥/环境变量。复核会增加逐引文模型请求（每信念最多30条候选引文）；实际研究须有授权和可承受预算。当前不认证来源日期、不做全网撤稿订阅，不等同F04模型迁移盲审或F03标准化保持实验。

## 10. 基准、技能验证和模型比较

### 10.1 F03：先校验，再冻结与评估

本地校验不访问数据库或模型；冻结写入数据库但不调用模型。评估调用模型，真实 API 可能计费，不是首次安装必做步骤：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli check-benchmark data/benchmark/reliable_sample.json
.\.venv\Scripts\python.exe -m autodidact.cli freeze-benchmark --path data/benchmark/reliable_sample.json
# 将输出 benchmark_id 换入下面命令，保留每次返回的 report_id：
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark "实际基准UUID"
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark "实际基准UUID" --use-memory
```

| 状态 | 含义与下一步 |
| --- | --- |
| `closed` | 可调用，不保证下次成功，也不代表来源结论可信 |
| `open` | 暂时熔断；等待 `retry_in_seconds`，检查密钥、服务状态或访问权限 |
| `half_open` | 一个恢复探针已领取，其他调用暂时阻断；成功关闭，失败再冷却 |
| `probe_available=true` | 冷却/探针租约已过，可由下一次实际操作领取探针；查看状态不会自动恢复 |
| 无记录 | 尚未进入该身份的准入，不可判断健康；mock、禁用嵌入通常无记录 |

连接错误、超时、408/425/429及500/502/503/504有限重试，默认总共最多3次（含第一次），指数退避加抖动；有效 `Retry-After` 短等待会被遵守，超过单次退避上限则结束本逻辑调用并保留冷却。鉴权401、403和明确验证页不重试当前提供方；不支持格式、404、不安全URL也不自动重试。预算耗尽与取消原样传播，不通过换提供方逃避预算。网页模型可能已提交的问题**不自动重发**，再次手动提问仍可能重复计费，应先查看网站会话。

搜索首选失败/熔断/无结果可走已配置后备；嵌入失败维持关键词降级；不可读来源维持研究收集器跳过/来源不足路径；核心模型耗尽尝试后交给既有学习失败/续跑流程，不伪造答案、降低证据门槛或无限循环。来源熔断按入口 URL 的 origin（协议/主机/端口）隔离，不逐重定向域记录；同源403/验证页可能短期阻断该源其他页面，404不会因此判整个网站失效。

每次实际适配器尝试重新预留预算，搜索每个后备提供方单独计账；熔断拦截不发请求、不占调用预算。一次 `web_reads` 是完整安全读取，内部可能含多个重定向 HTTP 请求，不是每跳计数。未知Token/费用保留估算预留；超时/崩溃不能证明远端没收到，仍可能已计费。健康统计不是账单、主动探测、自动告警或手动重置工具；当前无重置接口，配置/凭据变化会使用新身份，旧快照保留审计。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli verify-belief-audit $auditId $candidateModel --new-base-url $candidateEndpoint --limit 1
.\.venv\Scripts\python.exe -m autodidact.cli belief-audit-status $auditId
```

| 阶段 | 实际发生什么 |
| --- | --- |
| freeze | 保存人工清单、旧结论/范围/评分、支持边/URL/hash和新旧配置身份；不请求模型 |
| answer | 候选请求仅含question，不含旧结论/范围/身份/来源/分数/记忆；先保存等级0盲答 |
| verify | 跳过尚未盲答项；比较已存答复后，最多重读3个不同旧支持URL，再走F02独立核源/完整冻结旧来源排除/主张锚点及范围门控 |
| status | 只读显示已存答案和核源，缺项为null，不开始学习 |
| disputed | 只有合格独立原文反对原句且支持原子替代句、关系达门槛，才由既有事务标争议；原结论/置信度不自动替换 |

两收费命令每次默认处理1个未完成项，limit范围1–20，重复执行复用已有终态；不会自动处理下一批或调用Resolver。弃答/空答/模型失败为unknown；有异议但缺合格替代为needs_follow_up，模型一致也不是“旧信念已判真”。original_checks表示读取情况，original_evidence_review才是原文观察；original_sources_truncated=true表示没有重读全部旧URL。

候选模型/端点/采样指纹必须与冻结一致，旧结论或支持hash/边变化时拒绝继续收费，需重新审阅并换label冻结新批次。原始历史模型身份缺失明确null，configured_old_identity只是当前配置，不伪造旧归因。提供方远端同名模型漂移、题面隐性暗示与预训练污染不能靠指纹/字面检查消除。

每个审计项目使用阻断状态的专用占位目标/会话，不会被普通run拾取；收费阶段先持久计逻辑次数，沿用learning.max_retry，上限后不清零。F06内部每次尝试仍独立预算/观察，成功工作项可重放；预算/取消立即传播并保守计次，未知费用保留。终态unknown不无限自动重试，解决原因后用新label新批次。核源中途已更新来源/证据时可能触发冻结变化保护，此时不要强制续跑；检查已有F02报告后重新选样。外部调用与入库不原子，不承诺exactly-once。

报告kind：frozen_belief_audit、belief_audit_item、belief_audit_answer、belief_audit_review，可用show-report或工作台报告列表按kind浏览；F02独立核源报告仍kind=belief_review。当前无F04专属网页编辑/收费按钮，不把工作台只读审计变成任意修改真相。

## 16. F08：单用户运行计划与健康

运行计划只控制已有研究循环的次数、间隔和总时长，不改变证据、争议、预算与认知规则。以下命令在项目根目录执行；先按部署指南准备 `.venv`、PostgreSQL/pgvector、`.env` 和模型配置。**先显式 `init-db`，再启动工作台**；`serve` 现在只打开网页，不自动迁移或启动学习。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli service-health
.\.venv\Scripts\python.exe -m autodidact.cli check-run-plan .\config\run_plan.example.json
.\.venv\Scripts\python.exe -m autodidact.cli serve --port 8765 --plan .\config\run_plan.example.json
```

浏览器打开 `http://127.0.0.1:8765`，在“单用户运行计划与健康”查看计划、健康和最近进度，点击“启动计划”才可能调用付费模型。原“运行一轮”仍只跑一轮，不自动套用多轮计划。未初始化或数据库不可用时网页仍能打开，存活不等于可以研究。

示例计划 `config/run_plan.example.json`：`protocol=single_user_plan_v1`，最多3轮、轮间60秒、总时长1800秒。可复制到仓库外编辑并用 `--plan` 指定；EXE 首次补到个人目录 `config/run_plan.json`。约束：次数1–1000、间隔0–86400秒、总时长1–86400秒，文件≤16KiB；未知字段/字符串数字/自然语言命令均拒绝。计划不接受密钥或 shell。没有 `--plan` 的源码 `serve` 默认1轮。

不需要网页时，在前台显式运行（可能付费）：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli run-plan .\config\run_plan.example.json
.\.venv\Scripts\python.exe -m autodidact.cli service-runs
```

- 到达次数、预算耗尽、无待办、控制器忙、协议不兼容、失败或未知结果会停，不无限重试。循环间隔不是固定每天/整点调度。
- 网页“本轮后停止”让当前轮收尾，不撤销已经发送的请求；排队尚未开始可取消。达到总时长会取消在途轮，已保存工作项保留，未知费用仍按原账本保守记录。终端 Ctrl+C 或关闭服务也会取消本进程任务并等待清理；硬杀/断电不保证能保存最终状态。
- 重启只打开网页，不自动接续旧计划或后台索引。用户检查 `service-runs`、目标/会话后重新点击启动；已有 `checkpoints`、`retry-session`、`restart-session` 的兼容约束不变，不清零预算/次数。
- 同一数据库计划/备份/恢复用计划锁互斥，每轮前重查锁是否仍在；单轮学习仍持原控制器锁。这不是整个网页进程唯一，也不禁止旧 CLI 在计划轮间运行，维护前仍应停掉所有写者。
- `service-runs` 只读最近20条 `service_run` 持久快照，`running` 只是最后记录，不能证明进程活着；硬崩溃后可能一直保留该状态，系统不会据此自动恢复收费。

健康分两层：`GET /healthz` 只返回存活，不要求 Token、无数据库细节；`GET /api/service/health` 及其它服务 API 仍受 Host/Origin/Token 保护。未就绪返回503；CLI `service-health` 未就绪退出码1。只检查数据库可读、单一迁移 HEAD 和业务表存在，不认证索引/数据质量，不主动探测模型，也不会自动升级。

安全生命周期日志写在当前配置工作目录 `logs/service.jsonl`，单文件1MiB、保留3份轮转，只记时间、事件、运行/会话 UUID、轮次、白名单结果或异常类型；不写原始提示/回答、URL、密钥、异常正文。该约束针对新服务日志，不保证第三方工具及历史库内容全部脱敏。EXE 日志默认在 `%LOCALAPPDATA%\Autodidact\logs`。数据库断线时最终快照也可能写不成，应结合日志人工核查，不能当生产自动恢复/SLA。

备份、恢复及发布验证见[部署指南第12节](02部署指南.md#12-f08一致快照备份新空库恢复与交付)。本轮离线全量380通过/13数据库跳过，真实运维/恢复待V20。

## 17. F09：主题掌握与知识缺口

F09回答“在声明的范围内，哪些主题有历史表现支持、哪些还缺证据”，不是让模型给自己打分，也不是重新考试。它只读取已保存的F03可靠冻结基准及benchmark_run/benchmark_retention答卷，重算分数，不请求模型或搜索。没有历史观察时显示未评估，不补造数据；按本轮功能优先要求，不需要现在开始真实考试。

### 17.1 查看、保存、排学习目标

在已有数据库/可靠冻结基准后，用实际UUID替换占位值，在项目根运行：

```powershell
$f09FrozenId = '替换为已有可靠冻结基准UUID'
.\.venv\Scripts\python.exe -m autodidact.cli mastery $f09FrozenId
# 多个条件组时，从上一步groups复制一个实际64位group_id，不自动选择最好成绩
$f09GroupId = '替换为实际group_id'
.\.venv\Scripts\python.exe -m autodidact.cli mastery $f09FrozenId --group-id $f09GroupId
.\.venv\Scripts\python.exe -m autodidact.cli snapshot-mastery $f09FrozenId --group-id $f09GroupId
.\.venv\Scripts\python.exe -m autodidact.cli queue-mastery-goals $f09FrozenId --group-id $f09GroupId --limit 3
```

只有一个组时可省略 `--group-id`；无可靠观察时没有组，查看/保存仍可得到未评估画像。多个组不指定会返回selection_required，不合并分数，排队则拒绝。旧数组/模型裁判基准不能冒充可靠范围；mock、身份缺失、摘要/训练快照错误或不合法保持报告不参与掌握推断，拒绝报告ID会列出。

`mastery`是只读查询；`snapshot-mastery`显式保存不可变mastery_profile报告，相同依据/同日复用，不改旧画像、真值或信念；`queue-mastery-goals`只排明确弱项/退化/过旧/争议主题的普通研究目标，不运行它们。遵守原每日目标配额，最多新建limit个（1–20），已有触发目标另列existing_goals，终态也不反复创建/清零重试；有新依据才可能出现新触发。查看、保存、排队均不收费，实际run/工作台开始研究才可能调用付费服务。

### 17.2 如何看画像

范围由冻结题集 `category` 的中性单行主题标签声明；它必须和 `Belief.topic` 精确匹配，当前不推断同义主题或前置知识。分母只含该主题的held-out题，不含train，也不是整个领域的知识覆盖率。

| 状态 | 含义 |
| --- | --- |
| unassessed | 当前选定条件组没有可用主题观察，或还未明确选择组 |
| insufficient_evidence | 缺分集/真实保持/样本/校准/支持、最新unknown或有界输入不完整；不能当已掌握 |
| needs_learning | 已有明确评分弱项，仍需学习 |
| needs_review | 某分集/真实保持观察超过30天，或存在开放争议线索；不是自动判旧知识错误 |
| degraded | 同条件最近两次完整test观察下降至少0.2，是表现退化线索，不是因果证明 |
| provisional_mastery | 同范围/条件下满足工程门槛的暂定支持，不代表领域全部掌握或模型权重学会 |

状态与动作分开：整体证据不足时，如果另一个已完整评分分集确有弱项，仍可给出learn动作；不是把unknown当错题。只有待评估/unknown而无明确学习或复习依据时，action=assess，只提示未来补评估，不自动启动考试或排“判错”学习。

显示唯一题覆盖、test/transfer/retention分集、1−Brier校准、实际延时保持、最近12点test趋势及报告ID；重复测同题不增加独立题数。保持必须追到窗口内完整基线、相同模型/记忆/方法，并以数据库时间确认真实间隔；基线即时retention分数不冒充延时保持，无原先答对题时保持比例为未知。每个分集单独检查时效，新test不会掩盖陈旧迁移/保持证据。

条件组隔离模型/提供方/端点/采样、记忆模式及完整记忆/方法摘要；不同记忆快照不混算，不能跨组用最好成绩拼出掌握度。当前暂定门槛：各分集及可比真实保持≥0.8、校准≥0.8、至少5个不同held-out题ID和2次完整test观察、无陈旧/开放争议/输入截断，接纳信念均满足原来源质量与独立数门槛。不同题ID不证明语义独立，门槛未实证校准，因此综合mastery_score保持null，不伪造“掌握85%”。

知识侧复用正文质量/已知来源血缘与支持/反对摘录，输出证据质量、开放争议或有效反对线索比例、合格信念/来源/证据边引用及摘要；该比例不是事实错误率。即使F02已保存有效反对Evidence但尚未形成Dispute，也会提示negative_evidence/复习，不直接撤回旧信念或授予暂定掌握。历史最多100报告、500信念、1000条支持/反对证据边，拒绝或截断显式提示；页面另有展示截断，完整画像用CLI读取。不重新调用模型认证语义，不把引用数量当真值。

观察摘要使用现有规范JSON SHA256；来源同时保留原Source.content_hash与当次正文观察摘要，不保存原题面/答案到画像或规划。报告/来源/信念引用可用已有show-report/show-source/show-belief进一步核对；摘要只证明观察一致性，不认证来源或作者。

## 18. F10概念关系与前置知识

2026-10-21新增。先按[部署第14节](02部署指南.md#14-f10关系图谱升级与配置)备份并升级0010。图谱不是第二套真值库：每条断言绑定原Claim及原scope，通过库内ClaimEvidence原文、单独关系方向/范围观察、已接纳Belief和当前独立来源共同门控；共现或两端各自正确不构成因果。

九类方向均为 `subject → object`：is_a（是一类）、part_of（是组成部分）、requires（依赖）、causes（导致）、contradicts（明确命题矛盾）、supports（提供支持）、example_of（实例）、used_for（用途）、related_to（明确关联）。关系始终带原句范围；scope空表示未指定，不是无条件成立。相反方向/不同范围/不同主张分别保存，不静默合并。

### 18.1 查看、提议和显式模型核验

PowerShell在项目根目录执行。`<...>`均替换为真实库内UUID或原句文字；不要照抄占位符。先在既有认知审计中找到包含两个概念的原子Claim，不能把未读网页直接登记成事实。

```powershell
# 不请求模型、不写认知状态；limit默认20，最大50，offset最大10000
.\.venv\Scripts\python.exe -m autodidact.cli knowledge-graph
.\.venv\Scripts\python.exe -m autodidact.cli knowledge-graph --concept-id <概念UUID> --predicate requires
.\.venv\Scripts\python.exe -m autodidact.cli knowledge-graph --relation-id <关系UUID> --offset 0

# 仅登记candidate，不调用模型；两个标签须逐字出现在该Claim
.\.venv\Scripts\python.exe -m autodidact.cli propose-relation <ClaimUUID> "原句概念A" requires "原句概念B" "你的领域"

# 以下两条可能收费，必须显式--allow-model；预算/逐次观察沿用原规则
.\.venv\Scripts\python.exe -m autodidact.cli extract-relation <ClaimUUID> "你的领域" --allow-model
.\.venv\Scripts\python.exe -m autodidact.cli review-relation <关系UUID> --allow-model

# 不调用模型，只把当前状态/依据保存为不可变历史
.\.venv\Scripts\python.exe -m autodidact.cli refresh-relation <关系UUID>
```

`extract-relation`至多提议1边，再单独核对至多10个原文锚点。`candidate`为未达门槛；`supported`要求完整关系观察、当前匹配原文、已接纳supported/verified同句Belief、至少2个等级≥2且满足配置的独立来源及无冲突/截断；不称世界真值认证。`disputed`包含开放争议或有效反对线索，`weakened`表示曾支持但当前依据不足。查看即时重算、不修改缓存或历史；refresh或模型复核才追加快照。原来源文字变化使旧观察失效，需重新核原主张支持后再review，不能只靠重复提问放行。模型输出和Mock不供独立事实证据。

### 18.3 可选接入自主学习

## 19. F13记忆维护与可恢复归档

2026-10-21新增，先按[部署第15节](02部署指南.md#15-f13生命周期升级与回退)升级0011。范围是语义信念Belief和程序性技能Skill；Claim、原文、Evidence、Dispute、会话、冻结题集/答卷与关系引用不删除。生命周期独立于认识论状态：active参与默认使用，archived暂不参与；归档不是撤回/判假，恢复也不把provisional改成verified。

### 19.1 从建议开始，不自动清理

以下命令不请求模型或联网，不产生外部调用费用；数据库维护本身仍需资源。所有`<...>`替换为真实UUID，不照抄占位符。

```powershell

.\.venv\Scripts\python.exe -m autodidact.cli memory-maintenance --kind skill --state all
.\.venv\Scripts\python.exe -m autodidact.cli suggest-memory --kind belief --limit 5
.\.venv\Scripts\python.exe -m autodidact.cli suggest-memory --kind skill --limit 3
.\.venv\Scripts\python.exe -m autodidact.cli memory-maintenance --proposal-id <提议UUID>
```

规则扫描最多500个active对象/5000对比较，默认5条待处理提议；不是全库去重或语义认证。相同主题/范围/认识论状态的规范文字重复可建议group；65%词项重叠仅提示review，可能是矛盾而非同义。超过memory_review_days无更新/访问也只提示review，年龄不证明过时。旧日整合不回写，新的日整合可各生成最多3条信念/技能建议，**不会自动确认或归档**。

维护列表及提议各有分页offset/next_offset，详情可看before、current、stale、integrity_valid和已存决定；已执行后before与当前不同是正常的basis_changed，不等于再次执行。单项详情可看事件、归并代表和成员UUID。默认20条/最大50，offset上限10000；显示截断必须继续看原认知审计，不能据残缺页面认定证据完整。

### 19.2 显式归档、恢复与拒绝

先保存提议，再查看原句/范围/证据和影响，最后明确确认；没有confirm不会执行。

```powershell
# 仅保存提议，返回proposal_id，不改变记忆
.\.venv\Scripts\python.exe -m autodidact.cli propose-memory-change belief <信念UUID> archive "暂不纳入当前研究范围，保留原结论与证据"

.\.venv\Scripts\python.exe -m autodidact.cli apply-memory-change <提议UUID> "已审阅原范围和证据，确认改变默认可见性" --actor "本人" --confirm

# 恢复是另一个提议；执行后active、清空本项归并指针，不改置信度或证据
.\.venv\Scripts\python.exe -m autodidact.cli propose-memory-change belief <信念UUID> restore "重新纳入当前研究"
.\.venv\Scripts\python.exe -m autodidact.cli apply-memory-change <新提议UUID> "确认恢复" --actor "本人" --confirm

# 不执行提议，追加拒绝理由；不能覆盖已经执行的决定

```

技能将kind改为skill，其余过程相同。actor只是本机操作人声明，不是身份认证或专家批准。每次操作保留提议、前后快照、理由、版本和决策，Belief另有lifecycle_*历史。相同提议/决定重复调用返回原记录，不再次归档；相反决定不能覆盖，只能另建提议。提议后正文、状态、范围、证据、来源或版本变化，执行会拒绝旧快照；重新核查后另提，不清历史绕过。

### 19.3 非破坏性重复归并

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli propose-memory-change belief <重复项UUID> group "同范围同状态的文字重复，仅归组" --target-id <代表信念UUID>
```

### 19.4 浏览器、召回和续跑

运行serve后使用“记忆维护”区：选择belief/skill和active/archived/all，留空UUID查列表；填entity_id查单项/成员/历史，或只填proposal_id查提议，两者不混选。填写action/reason/可选group代表后“仅保存提议”，再查看并用确认按钮执行/拒绝；手工切换查看对象时清除另一个UUID。全部内容纯文本，查看不写、不调用模型，写动作有原Host/Origin/Token保护和控制器锁。

### 20.2 冻结人工问题，再逐阶段授权

```powershell

.\.venv\Scripts\python.exe -m autodidact.cli run-cognitive-review $reviewId --phase blind --allow-model
```

freeze只读关联认知并写冻结报告，不发送模型；运行可能收费且不自动迁移。含网页的阶段另加--allow-web；未授权不会提交网页。一次命令只运行一个阶段，模型调用沿ProviderRuntime/ObservedLLM或WebModelService及原预算/控制器锁；API可有F06有界重试，网页不自动重发。

盲答只见问题，不见topic、来源身份、旧认知或别的初答。全部初答已有确定结果且至少两项成功才批判；综合还要求批判成功。批判须指向成功source_id并逐字quote盲答原文，非法引用保留失败而不作论证边；锚定不证明批判语义正确。综合只可引用成功初答来源、列出未解决/待核源；不比较多数票。论证图连接阶段结果、原ModelObservation及冻结关联，supports/attacks/qualifies仅模型意见，不是F10事实支持/因果图谱。

### 20.3 恢复与失败边界

- success复用原结果，不重发；明确failed默认不重试，人工处理原因后同一阶段另加--retry-failed。
- uncertain表示入场已保存、结果未知，可能已发送/计费。先查看观察与账户；若已落库成功观察，可从观察恢复而不重发。否则必须人工承认重复风险后加--retry-uncertain（网页仍须--allow-web），没有exactly-once保证。
- 每来源/阶段逻辑入场上限min(max_retry,3)，取消/预算中断保守占次。API每次逻辑入场仍可能触发F06物理重试，费用不能只按阶段数估算。每次run总限时900秒，已成功阶段保留；只读库请求SQL5秒/整体20秒。
- 下游入场后禁止重跑上游，防止把旧批判拼接到新答案。关联认知/来源身份改变拒绝旧批次继续收费；新建不同label清单保留历史，不清空次数/报告，也不自动恢复付费任务。

## 21. F12方法泛化、反例与显式采用

目标：把“从成功记录总结一个方法”与“方法真的有用、适用在哪里、是否允许规划器采用”分开。方法只提供文字研究建议，不执行代码、修改核心逻辑或扩大权限。本轮基础代码已接通但未测试；真实泛化效果仍待V25，不把一个正增益称为自动变聪明。

```powershell

# 修改自己的清单，不直接用模板中的空UUID冒充真实出处

```

注册会保存不可变definition，**暂停此技能原自动采用**；不修改原procedure/Skill.version/认识论历史，也不是已经验证。字段是人工适用性声明，不认证专家。包含词任一命中即可，排除词优先，按规范化文字匹配实际目标题面；不是语义条件/任务难度证明。修改定义需新label，旧定义和出处快照不覆盖。

新增**任何人工案例**都会推进案例版本、暂停旧采用并使旧对照过期，需重新冻结/评估/确认；重复同一记录只复用，不重复暂停后来的新采用。正常学习收尾会另存skill_use_outcome同会话关联，保留旧计数/经验置信度，不自动判方法有效/失效，也不凭一次成功启用。人工复核这些观察后再记录案例或回退。

### 21.3 冻结可靠独立任务与重复A/B

先按第11节可靠题集协议freeze-benchmark。F12只接受有人工independence_review的可靠真值题集，不接受旧rubric模型裁判；test/transfer合计至多20项，其中至少5项通过方法文字条件、test/transfer各至少2项，另至少1项明确不适用的边界负例。原可靠协议仍要求独立retention分集，但F12不运行它，也不冒充真实保持实验。现有3题可靠sample不满足F12门槛，需要你另行审定独立题集。

复制config/skill_experiment.example.json，填definition_id、benchmark_id、label、2–3次repeats、负例题ID、是否固定使用当前接纳记忆，以及实际人工separation_review。负例必须是test或transfer中被方法规则排除的题；判断只看题面，与规划目标题面门控一致，不拿category偷偷扩大适用性。程序拒绝评估题与实际学习目标直接重合、或题面直接出现在方法中；人工还须检查语义/家族/答案和记忆泄漏，结构检查不能替代它。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli freeze-skill-experiment config/skill_experiment.example.json
# 填freeze返回的真实experiment_id
$experimentId = '00000000-0000-0000-0000-000000000000'
.\.venv\Scripts\python.exe -m autodidact.cli skill-methods --experiment-id $experimentId
```

freeze仅写报告不调用模型。冻结模型/端点/采样、记忆、与规划器相同的方法参考文字、定义/案例版本、真值hash、实际训练快照和交错答题顺序。两臂只有是否提供此方法不同；每题每重复两次调用，顺序预先交错，不取最好组。

负例两臂都不提供方法，只观察文字边界门控及相同控制条件噪声，**不将其分差记为正增益，也不证明强行使用此方法不会有害**。方法的研究场景泛化、真实语义反例和因果收益仍需要后续独立实证。

## 22. F05人工复核操作闭环

这一入口不编辑真值。先在认知审计查看原文/范围/历史，再创建冻结提议，最后逐项按摘要批准或拒绝。三种action：

| 动作 | entity_id | 批准的实际效果 |
| --- | --- | --- |
| review_belief | 已有信念UUID | active且未撤回才可排原文复核，复用F02旁路；不升置信/恢复归档 |
| investigate_dispute | 已有争议UUID | 仅open/investigating/unresolved排调查，复用原四结果流程；不重开已解决争议 |
| annotate_source | 已有来源UUID | 保存经人工批准的书目校正批注，不覆盖Source字段/正文/质量或血缘 |

批准命令不调用模型或网络。但已有授权计划可能在后续轮次选中新目标并收费；只想排队时先停止计划并等当前轮结束。批注不会被自动读者当作新事实或书目信息，所有冲突批注均保留，不以最后一条覆盖旧记录。

### 22.1 用命令保存提议

复制模板到新的个人文件，不覆盖模板。把request_id改为`[guid]::NewGuid()`生成的新UUID，entity_id替换为实际记录，补真实理由：

```powershell
Copy-Item -LiteralPath config/human_review.example.json -Destination config/my-human-review.json
[guid]::NewGuid()
notepad config/my-human-review.json
.\.venv\Scripts\python.exe -m autodidact.cli propose-human-review config/my-human-review.json
.\.venv\Scripts\python.exe -m autodidact.cli human-reviews --state pending
.\.venv\Scripts\python.exe -m autodidact.cli human-reviews --proposal-id <提议UUID>
```

清单不超过64KiB，严格字段；同request_id和完全相同输入重试返回原提议，改变对象/动作/理由必须新ID。保存只新增不可变提议，不排目标。上述config/my-human-review.json已被Git忽略，另起文件名须自行保护，不上传私人复核资料。来源批注还必须增加correction：

```json
"correction": {
  "field": "author",
  "value": "原文实际作者文字",
  "excerpt": "包含原文实际作者文字的逐字摘录"
}
```

field只允许title/author/published_at；日期值须YYYY-MM-DD。value必须逐字位于excerpt，excerpt必须位于已入库Source.extracted_text，不能凭模型输出/外部URL自称有据。只做锚定，不认证作者/语义/出版日期；页面meta有而正文无时本入口不接受，需按原路径获取可读材料。非来源动作禁止correction。

### 22.2 查看冻结依据后决定

详情返回payload.sha256、冻结原依据、current_basis、basis_validity和旧决定。将刚查看的摘要填入命令：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli decide-human-review <提议UUID> approve "核对原文后请求复核" --proposal-sha256 <payload.sha256> --actor local_user --confirm
# 或拒绝；过期提议仍可以拒绝，不会执行原动作
.\.venv\Scripts\python.exe -m autodidact.cli decide-human-review <提议UUID> reject "依据已变化，另提新请求" --proposal-sha256 <payload.sha256> --actor local_user --confirm
```

只批准当前依据仍一致的提议。正文/书目/来源质量、原证据、范围、争议/生命周期等快照变化即拒绝；不自动刷新提议后继续执行。信念/争议原证据至多各200条、整体报告至多2MiB，超限拒绝，不截断批准。已有活动信念复核任务复用；争议已有任务包括终态都复用，不清重试或上限，返回created=false不代表调查重新启动。配额不足无批准事件/半个目标，稍后重新查看再确认。

决定按提议UUID唯一，重复完全相同决定/摘要/actor/理由复用原结果，反向或修改理由不能覆盖；另提新请求保留旧历史。目标/派生关键词索引或来源批注与决定同事务；取消/失败会回滚未提交动作。拒绝不要求当前依据仍有效，不改变认知。actor只是本机声明，不是生产身份/专家认证，也不强制提议人与决定人为两个人。

### 23.2 如何读成绩、保持和费用

可靠基准以原冻结真值/原答卷重算，逐题显示答复/置信度、固定规则分数和原预期答案，汇总完整度/unknown、Wilson区间、校准及分集指标；有未知时准确率只是已评分子集，不当总体通过。含题面答案，因此仅供本机授权审计，不适合向参测者或公网开放私有题库。

保持详情必须能追到同题集/同条件完整基线、原保持分集及真实数据库时间，间隔达min_retention_hours才列保持率/分差；从原先正确题重算，未复测完整不填保持率。四组迁移A1/A2/B1/B2从原答案分别复算，组内模型身份与固定记忆/训练摘要须一致，仅完整对照给分差，不自动换模型。F12重用固定重复全部结果/未知历史与退化门槛，界面不启用方法。

UTC资源表分开settled（已知结算）和reserved（未结算预留）；没有有效actual显示未知，不把预留叫实耗。invalid_n>0说明聚合不完整，非法/非有限旧值不当0；estimated_usd依配置价格估算，0不证明免费或真实账单。窗口费用不强行归属某份报告；模型观察错误和OperationEvent运营错误是重叠审计层，不能相加。安全类别外统一other_or_unknown，不展示异常正文/prompt/response。

总览记录包括失败/占位等会话，跨度和记录日数不是有效学习日数或30天实验完成证明。没有历史就显示缺测，绝不插造30天样本；长期结论仍需真实固定条件、多次实验、独立题集和保持证据。
