# 来源血缘、阶段中点续跑与混合检索

更新时间：2026-10-03。本文描述本次代码增量；“已接通”不等于已通过真实运行验收。本轮按用户要求没有运行 pytest，没有升级真实数据库、调用真实模型或构建 EXE。

## 1. 这次解决什么问题

| 问题 | 现在的处理 |
|---|---|
| 几家网站转载同一篇材料，被误算为几份独立证据 | 将已识别的多级来源依赖连成图，再按依赖连通分量、发布者和正文哈希合并证据计数 |
| 综合到一半、答完几道题后中断，下次全部重新做 | 在同一个学习会话内保存成功工作项；下次重放控制流时复用已保存结果，只补尚未完成的调用 |
| 只查最近信念，容易漏掉较早的相关知识 | Belief、Claim、Goal 统一使用关键词与 pgvector 语义召回，按排名融合；最近记录仅作为兜底 |

这仍然是持久自学习研究智能体。检索只是帮助规划、冲突发现与记忆定位；不能把检索命中、候选 Claim 或模型解释直接变成真值。

## 2. 复杂来源血缘

### 2.1 可记录的关系

- `canonical`：网页 canonical 声明。
- `redirect`：实际读取的请求入口与最终地址。
- `same_work`：正文元数据中的 DOI、文章公共地址、文章级 JSON-LD 的 sameAs。
- `reprint`：original-source / syndication-source 声明，以及明确标注“转载自、原文链接、reprinted from”等的链接。
- `derived_from`：文章级 JSON-LD 的 isBasedOn。
- `identical`：正文哈希相同但地址不同的副本。
- `cites`：可识别的普通引用，只记录图边，不据此合并独立来源。

支持已入库图上的跨域、多级传递依赖和环，例如 A 转载 B、B 转载 C，那么 A 与 C 不是两票独立证据。指向尚未抓取的同一个原始 URL 或 DOI，也可以构成共同来源；DOI 身份做大小写归一化。

引用了同一本教科书的两个独立实验，不会仅因 `cites` 边而被当成同一实验。反过来，明确改编或转载同一工作，必须保守扣减独立票数。

### 2.2 如何进入决策

`SourceLineage` 在来源入库时保存关系；晋升策略、四结果争议决议、闭卷独立核源共用扩展后的独立性分组。缓存的核源材料在重放时仍会重新检查已知依赖关系。

网页自报的血缘是不受信任的声明，最多用于减少独立票数，不能提高证据等级、证明事实或执行指令。关系图不能替代原文支持检查。

目前只解析明确的结构化信息和局部链接标注，不自动递归下载整条引用链，也不声称能发现隐蔽抄袭、未披露合作或所有真实发布者关系。遍历最多 32 层、每层最多 2000 条边及总节点保护；超限时采用保守的“不完整血缘”分组，而不增加独立票数。

### 2.3 查看与回填

```powershell
autodidact source-lineage "https://example.org/article"
autodidact rebuild-lineage --limit 200
```

回填读取已有 Source 元数据，不重新联网抓取网页。没有保存的旧 HTML 元信息无法凭空恢复。重复执行会跳过已标记完成的来源；显示 remaining 为 0 表示当前回填结束。

已有信念的历史置信度、旧 source_count 和旧评估不会因图回填被无条件覆盖。新晋升与争议处理使用新的独立性判定；旧结论仍须走复核与争议流程。

## 3. 阶段中点续跑

### 3.1 如何保存

新会话在规划开始前就落库，并标记 `durable_replay_v1`。工作项以“学习会话 + 类型 + 输入哈希”唯一保存成功结果，覆盖规划上下文、搜索命中、网页正文、综合结果、逐段原文支持判断、冲突比较、闭卷试卷、各题答案、独立核源材料及裁判结果、反思和争议调查中的模型调用。

规划上下文与研究材料冻结，避免恢复时因为自己的新增信念而改变原来的输入。闭卷答案缓存不会获得来源正文或参考答案，仍保持现有隔离协议。

预算暂停、进程退出、工作台停止后，下次 `run-once` 或 `run` 优先继续最早的可续跑会话。数据库控制器锁仍限制单个写入控制器；本次不是分布式任务队列。

已完成的数据库效果保持幂等：同会话 Claim 和证据复用；同一 Claim 的晋升/再观察历史不会重复；同结果评估、目标失败次数、技能结果统计均有重放保护。若恢复时核源结果确实改变，评估历史保留追加版本，而不是擦除旧审计。

### 3.2 使用命令

```powershell
autodidact checkpoints
autodidact run-once
```

`checkpoints` 显示未完成会话 ID、阶段、成功工作项数和错误。成功返回中有 `session_id`、`resumed`。

预算用尽不会自动关闭尝试，也不会计入会话异常重试次数。等待次日预算窗口或核对原配置后再运行即可；预算账本不会因续跑清零。连续异常达到 max_retry 会阻塞该目标，保留所有工作项。

排除故障后，人工解除阻塞：

```powershell
autodidact retry-session "会话UUID"
autodidact run-once
```

模型、端点、学习策略、采样配置或目标内容改变时，返回 `resume_incompatible`，防止不同实验条件混用。可以恢复原配置继续；如果确定要采用新配置重新研究，显式运行：

```powershell
autodidact restart-session "会话UUID"
autodidact run-once
```

restart-session 人工结束旧尝试并把目标重新排队，下次创建新会话；不删除旧证据、信念、工作项、历史或资源账本。

### 3.3 准确边界

这是成功工作项级续跑，不是恢复模型内部推理状态、半段 HTTP 正文或流式输出 token。外部请求成功但结果尚未提交数据库时，如果进程被强制终止，该请求仍可能重发；没有承诺跨外部服务的 exactly-once。

恢复会重新经过本地控制流和幂等检查，不是直接跳过所有先前函数。旧版会话缺少工作项快照，继续采用保留证据后重试，不伪造精确续跑能力。每日整合与冻结实验的维护任务不复用学习会话缓存，避免缓存污染独立实验。

## 4. 混合检索

### 4.1 检索组成

- 关键词：英文单词与中文二/三字片段分词，PostgreSQL simple 全文检索与 GIN 索引；旧数据还可走有限数量的直接文本匹配。
- 语义：pgvector 1536 维向量与 cosine HNSW 索引，严格匹配嵌入提供方/端点/模型/维度指纹；兼容旧 Belief 向量缓存。
- 融合：关键词与语义排名使用 RRF；精确短语额外加分。某类型两路无命中时才使用低权重最近记录。

返回的 score 是相关性排序分数，不是事实概率。结果保留 kind、状态及各通道排名。

已接入学习规划中的相关认知上下文、Claim 与旧 Belief 冲突比较，以及网页工作台提问。工作台只检索 supported / verified 且无开放争议的信念，仍展示证据，不把 Claim 或 Goal 当成已接受知识。

新 Goal / Claim 写入会产生关键词索引，在学习循环中尽力生成语义向量；新 Belief 保留现有向量写入路径。历史数据和争议新信念可分批统一回填。嵌入关闭、服务失败或预算不足时，关键词检索仍可工作。

### 4.2 操作命令

```powershell
# 不调用嵌入服务，只建立或修复文字索引
autodidact rebuild-retrieval --limit 200

# 已配置1536维嵌入服务时，分批生成缺失或过期向量
autodidact rebuild-retrieval --vectors --limit 100

# 每次跳过已经符合当前文本与模型指纹的条目，可重复执行
autodidact search-memory "PostgreSQL 并发唯一约束" --limit 10
autodidact search-memory "阶段检查点" --kind goal
autodidact search-memory "研究结论" --accepted-only
```

嵌入配置沿用 `.env.example` 中的 EMBEDDING_PROVIDER、EMBEDDING_BASE_URL、EMBEDDING_API_KEY、EMBEDDING_MODEL。关键词模式不需要嵌入密钥；语义回填会消耗提供方调用与每日预算。

统一索引是派生缓存，重建不会改写目标意图、Claim 原文或 Belief 状态。中文分词不是专用语言模型；排序质量、大规模查询延迟、ANN 过滤召回率仍需后续实测调优。
