# 项目路线评估与初始构想对照

更新：2026-09-24。核对代码基线：`d3e8e96`，其功能代码来自 `d374b27`。本文件分析完成路线后的预期效果，不表示这些效果已经发生。安装操作见[部署安装与验证手册](部署安装与验证手册.md)，历史和代码说明见[完整交接文档](项目全量迁移交接与技术说明.md)。

## 1. 结论：方向一致，验证与产品化缺口仍然明显

当前路线保留了最初最关键的三件事：学习状态独立于模型、知识有证据和变化历史、冲突需要调查。没有出现把项目变成通用聊天壳或仅靠向量检索拼答案的根本性转向。

如果“功能全实现”指原始交接稿 A—J 阶段加上当前可靠性路线，并且通过验收，预期产物是一个**限定领域、受预算约束、能够积累和修正知识的长期研究系统**。你提供使命，它可以连续提出学习目标，检索资料，维护信念和争议，检查掌握程度，形成学习方法，并输出可核查的成长报告。

功能代码齐全不保证能力增长。初期构想中的“30 天后更聪明”是待验证的实验假设，结果可能为正、接近零，甚至在来源质量差时变负。完成路线应带来测量、诊断和改进这种变化的能力，而不是保证某个提升百分比。

不能给出可信的“偏离初衷 10%”之类数字：项目尚无冻结验收权重和长期实验结果。更有用的判断是：**架构方向偏差小；当前实现与目标效果差距大；对参数自训练、通用自主行动的期待超出已认可的 V0.1 范围。**

## 2. 全部完成后，实际能得到什么

| 场景 | 完成并验收后的预期行为 | 你可以检查的产物 |
|---|---|---|
| 给一个长期领域 | 生成有价值的问题，发现低把握知识、前置概念和未解决矛盾，按预算排序 | 目标池、优先级理由、执行记录和成本 |
| 学习一个主题 | 搜索多个来源，读取材料，形成原子主张，保存原文引用和证据质量 | 来源与摘录、Claim、证据关联、初步信念 |
| 遇到错误或不确定结论 | 复核出处、条件和范围，无法判断时保留不确定性，安排补救学习 | 失败分类、反思、重试或前置目标 |
| 新模型反对旧知识 | 保留旧信念历史，独立调查双方证据，给出保留旧/采用新/条件化/未解决结果 | 争议记录、双边证据、决议与历史 |
| 重复研究同类问题 | 利用已有知识与经验证的方法减少重复阅读，提高任务表现 | 记忆检索记录、技能使用结果、质量与成本对照 |
| 更换推理模型 | 保留数据库状态，在冻结题集和同一记忆快照上对比旧/新模型 | A1/A2/B1/B2 分数、记忆增益和退化样本 |
| 运行 30 天 | 定期测试能力、保持度、迁移和校准度，区分数据库增长与能力增长 | Day 0/7/14/21/30 报告及可复现评估数据 |
| 使用网页模型 | 在你授权并手动登录的站点咨询，回答作为等级 0 观察，再查原始来源 | 模型观察、引用验证和提供方失败记录 |

例如你给它“理解无人机定位与姿态估计”的使命。理想流程是：研究 IMU/GNSS/VIO → 发现不懂四元数 → 增加前置目标 → 隔天复测 → 遇到“视觉失效时能否继续估计”的分歧 → 调查短时与长期条件 → 形成更精确的信念。一个月后，你能看到它在哪类新题上比第一天表现更好，以及这个变化究竟来自新模型还是它积累的知识。

用户友好的“提问→带证据回答”“目标管理”“查看争议”网页界面仍需另行实现。研究内核与原始路线完成，不会自动生成可双击的桌面产品或网页工作台。

## 3. 与初期构想逐项比较

| 初期想法 | 当前情况 | 全路线落地后的偏差或边界 |
|---|---|---|
| 开始只有阅读、思考、记忆、上网 | 已有模型、网页读取、检索和持久对象 | 思考始终依赖外部/本地模型能力，系统会围绕模型积累经验 |
| 后期自己决定学什么 | 已有模型提目标、评分和跟进目标 | 能在使命、来源和预算内自主选题；使命、权限与资源仍由你提供 |
| 长期成长而非每次从零开始 | 已有 Goal/Belief/Evidence/History 等 | 可以跨会话积累，但需验证知识和技能真的被后续任务使用 |
| 学会质疑更强或更新的模型 | 已有冲突检测与四结果决议服务 | 自动调查链路补齐后接近原意；裁决仍有误判，不是绝对真理检测器 |
| 理解自己学到了什么程度 | 当前模型辅助评估还会同时看到来源 | 严格闭卷、迁移、保持和校准测试接通后才能合理回答 |
| 换模型不丢掉自己 | 数据库独立于 LLM | 能保留状态；模型变化仍可能影响召回、理解和使用记忆的质量 |
| 学会方法并改善学习方式 | 有 Skill 表，缺技能提取和使用闭环 | V0.1 可积累经过验证的方法；自动修改学习策略并做 A/B 测试属于后续阶段 |
| 阅读文本/Markdown/PDF | 目前读取器支持网页 HTML 与纯文本响应 | 本地文件导入、PDF 提取、页码/段落引用尚需显式列入实现任务 |
| 网页聊天模型也可作为认知工具 | 有通用 Playwright 原型，未主循环接线 | 原方向保留；站点界面、登录与访问限制使它只能是可选渠道 |
| 30 天证明成长 | 有简单 benchmark 和统计，缺完整实验 | 能测量是否成长，无法预先保证原稿中“提升 20%”等目标 |

需要明确区分两种“偏差”：未实现是工程缺口；不训练模型参数、不给任意工具权限，是最初已经认可的范围选择。若将“自己学习”理解为自行产生任意新能力、无需现有模型、自动训练权重或自行扩张权限，那么现在这条路线达不到，须单独定义更后期研究计划。

## 4. 完成当前路线仍不会自动得到的能力

- 基础模型参数变化：知识和经验主要保存在外部状态，没有 LoRA/微调/RL 训练管线。
- 无条件持续提高：过期资料、重复证据、评估泄漏和错误记忆都可能降低表现，需要纠错和可回滚实验。
- 完整现实实验能力：当前学习以文本研究为主，尚未接数学验证器、仿真、硬件或实验控制系统。
- 全自主通用执行：它不会自行获得登录、支付、发帖、任意 shell、核心代码自修改等权限。
- 即装即用的网页或 EXE：目前 CLI 是已实现入口；产品界面、安装向导和打包资源管理需要独立交付。

## 5. 让路线更贴近初衷的建议顺序

| 顺序 | 小里程碑 | 验收依据 |
|---|---|---|
| 1 | 可重复安装、专用 PostgreSQL 在线测试、一次带真实模型的研究演练 | 安装日志、迁移记录、可查的来源/Claim/会话；不把跳过测试算通过 |
| 2 | 隔离出题、闭卷回答、核源与评分，冻结小型私有基准 | 回答阶段看不到原文或答案；分数能复算，有人工核查样本 |
| 3 | 接通争议调查、网络读取边界、阶段恢复和调用预算 | 故障注入不丢旧状态；费用可限制；四种决议有独立证据 |
| 4 | 让记忆和技能真正影响后续行为 | 同模型、同题集、同预算，有记忆组与无记忆组比较；技能不只是存一条 JSON |
| 5 | 接入本地文档/PDF与可选网页模型，并统一保存模型观察 | 能定位页码/原文；模型回答保持等级 0；单渠道失败可降级 |
| 6 | 模型迁移、30 天实验和学习策略比较 | A1/A2/B1/B2、保持测试、成本与延迟，以及负增益样本都公开记录 |
| 7 | 本地网页工作台，再考虑面向普通用户的安装包 | 能创建目标、查看证据/争议、发问和停止运行；界面操作不绕过知识门槛 |

早期可以做一个薄的只读状态界面帮助观察，但不宜让聊天、打包和大量模型适配占据评估工作的时间。公开问答前，应定义回答如何引用已接受信念、如何展示未解决争议、如何拒绝把待验证主张当作结论。

## 6. 如何量化“偏差”和“效果”

先冻结一张你认可的验收表，不用代码行数或模块数代替完成度。建议记录：目标自主生成比例、独立证据可追溯比例、高置信错误率、争议积压/解决率、保持度、迁移题表现、费用和恢复成功率。

对于同一组评分一致的私有题集，定义：

```text
旧模型记忆增益 = A2（旧模型 + 固定记忆）− A1（旧模型单独）
新模型记忆增益 = B2（新模型 + 同一记忆）− B1（新模型单独）
基础模型变化   = B1 − A1
长期变化       = 同模型同条件下 Day 30 − Day 0
```

题目答案不能进入学习资料；闭卷阶段只能使用实验条件允许的记忆，不能临时看核验来源。固定或记录模型版本、题集、记忆快照、提示词和预算，并检查重复样本。单次小题集涨分不是稳健结论，应报告逐题结果和重复运行波动。

到那时，可以明确地说“在哪些任务上增加了多少能力、付出了多少成本、哪些方面仍未达到构想”。当前尚不具备给整体偏差或能力增益报一个百分比的证据。
