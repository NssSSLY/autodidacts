## 2. 新版本的环境与升级

环境仍是 Python 3.12+、PostgreSQL 16/pgvector、模型 API 和可用检索网络。Docker 可用于数据库，本机 Python 负责学习器。先按[部署安装与验证手册](部署安装与验证手册.md)准备数据库；有学习记录时先备份。

```powershell
Set-Location 'C:\file\project\autodidact_v0_1'
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli bootstrap
```

最新数据库版本为 `20261002_0004`。新增 `operation_events`、`research_reports`，以及 `skills.metadata_json`。原有目标、来源、主张、信念、争议和历史行不删除。无版本的 0001/0002/0003 旧结构仍先严格识别再升级。

降级 0004 会删除新增预算记录、研究报告和技能验证元数据，所以回退前需单独备份这些数据。新旧进程不能同时操作一个学习库；升级时先停止旧进程。本轮只编写迁移，没有连接你的数据库执行迁移。

## 3. 最直接的使用方式：本地网页

在项目根目录配置 `.env` 中的数据库与模型，然后运行：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli serve --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。网页固定绑定本机，当前不作为公网多用户服务。操作顺序：加入明确的目标 → 开始一轮学习 → 查看输出 → 再围绕积累的信念提问。

“提问”会显示模型解释和它引用的已保存信念/来源。解释作为待核验建议；提问不会直接新增信念。缺知识时应创建学习目标。页面的中断按钮取消当前网页发起的循环；下一次运行保留已有证据并重新尝试中断目标。

也可以使用命令行：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli add-goal "研究视觉定位失效时惯性定位的有效时长"
.\.venv\Scripts\python.exe -m autodidact.cli run-once
.\.venv\Scripts\python.exe -m autodidact.cli run --max-cycles 3
.\.venv\Scripts\python.exe -m autodidact.cli queue-disputes
.\.venv\Scripts\python.exe -m autodidact.cli status
.\.venv\Scripts\python.exe -m autodidact.cli report --days 30
```

自动争议目标在后续循环处理，不是在发现冲突的一瞬间直接改写信念。已存在的旧争议可以用 `queue-disputes` 加入调查队列。

## 4. 闭卷评估与预算配置

新的配置有兼容默认值，不必为了运行补齐每一行。可以在 `config/agent.yaml` 的 `learning` 内设置：

```yaml
evaluation_questions: 3
require_independent_verification: true
max_daily_model_calls: 200
max_daily_tokens: 1000000
max_daily_searches: 100
max_daily_web_reads: 200
max_daily_web_model_calls: 20
max_daily_embedding_calls: 200
max_daily_estimated_cost_usd: 0
max_response_bytes: 2000000
max_redirects: 5
max_dispute_investigations: 3
memory_review_days: 30
auto_consolidate_memory: true
```

预算和每日目标配额以 **UTC 日**为边界，UTC 0 点对应北京时间 8 点。资源在调用前预留，进程中断或提供方未返回使用量时保留预估扣减；不会因重启就重新得到一份预算。令牌按 UTF-8 字节数及输出上限保守预估，有提供方实际使用量时再调整。

金额预算为本地估算，需要在 `.env` 填写提供方合同中的输入/输出价格；它不是提供方账单上限，搜索、浏览器订阅和嵌入费用也需单独考虑。仍应使用提供方自己的额度限制。0 表示关闭金额估算门槛，调用和令牌门槛仍有效：

```dotenv
LLM_MAX_OUTPUT_TOKENS=2048
LLM_INPUT_USD_PER_MILLION=0
LLM_OUTPUT_USD_PER_MILLION=0
```

可以指定独立裁判模型；不设置时复用同一模型，但仍使用独立请求且不共享对话上下文：

```dotenv
JUDGE_LLM_MODEL=你的裁判模型标识
JUDGE_LLM_BASE_URL=https://你的裁判服务/v1
JUDGE_LLM_API_KEY=你的裁判密钥
```

闭卷答题只看到问题与本轮学到的命题。作答完成后另行检索来源，排除本轮已读 URL、相同发布者、正文哈希和可识别的 canonical 同源资料，再核对摘录。无法得到独立验证来源时保持未通过。模型裁判仍可能出错，不能把程序高分视为事实证明。

## 5. 记忆与技能

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli consolidate
.\.venv\Scripts\python.exe -m autodidact.cli skills
.\.venv\Scripts\python.exe -m autodidact.cli refresh-profiles
```

每日快照保存在 `research_reports`。技能先是 candidate，只作为候选方法保存；需要至少 5 道独立任务的冻结基准进行对照验证。将命令输出中的真实 ID 替换到下文，不保留占位文字：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli validate-skill 技能ID 冻结基准ID
```

带方法组表现优于基线时标记 validated，之后匹配相关目标时进入规划上下文，并记录实际使用的成功/失败数。一次小样本正增益不等于稳定有效，需要重复实验和人工复核。证据关系图保存“来源支持信念”和“目标由另一目标产生”等已有数据库关系，不自行创造因果结论。

## 6. 冻结基准与模型迁移

先准备不会交给学习器研究的私有 JSON 题集，每题至少有 question，以及 rubric 或 accepted_answers。accepted_answers 使用精确答案匹配；开放题使用模型裁判，报告会标注两者区别。

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli freeze-benchmark --path .\data\benchmark\sample.json
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark 冻结基准ID
.\.venv\Scripts\python.exe -m autodidact.cli evaluate-benchmark 冻结基准ID --use-memory
.\.venv\Scripts\python.exe -m autodidact.cli compare-models 冻结基准ID 旧模型标识 新模型标识
.\.venv\Scripts\python.exe -m autodidact.cli show-report 报告ID
```

`compare-models` 默认两个模型使用 `.env` 的兼容 API 地址与密钥。如果新模型来自另一地址，添加 `--new-base-url`；密钥不同则在 `.env` 设置 `MIGRATION_NEW_API_KEY`。迁移报告保存固定题集、固定记忆和四组逐题结果；比较本身不切换运行模型，也不覆盖信念。

如需自动采集 Day 0/7/14/21/30 实验，把已冻结题集 ID 写入 `.env`：

```dotenv
BENCHMARK_SNAPSHOT_ID=实际冻结基准ID
```

之后运行学习循环时会在到期时采集同模型、有记忆/无记忆对照，并受预算控制。这会增加模型调用。没有运行的日期不会补造分数；报告同时记录名义里程碑和实际经过天数。它没有替你持续启动进程，长期运行仍需你安排电脑或服务器。

## 7. 本地文档、网页模型和向量回填

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[documents]"
.\.venv\Scripts\python.exe -m autodidact.cli import-document 'C:\资料\定位方案.pdf'
.\.venv\Scripts\python.exe -m autodidact.cli import-document 'C:\资料\研究笔记.md'
```

导入文件创建来源及目标，初始证据等级为 1。PDF 单次最多 100 页、20 MB，保存页码标记；扫描PDF须先做OCR。TXT/Markdown 使用 UTF-8。本地文档不会因为由你提供而自动成为高等级事实。

网页模型需先安装 Chromium，并按获授权的网站填写 `config/web_models.yaml` 的选择器，使用手动登录的持久化浏览器目录：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m autodidact.cli web-ask 提供方配置名 "说明视觉惯性定位的常见失效条件"
```

`.env` 设置 `ENABLED_WEB_MODELS=配置名` 后，主循环会咨询该渠道，将回答作为查询规划线索。回答和其中的引用都需要独立核查；网页模型回答不直接作为事实证据。界面失效、超时和登录不可用时降级，系统不会自动登录或绕过限制。

向量仍为 1536 维。旧库没有指纹的向量不会与新模型的向量混合比较，先回退最近信念；配置嵌入服务后可分批补齐：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli rebuild-embeddings --limit 100
```

再次执行会跳过已匹配当前指纹的记录。`--force` 强制重建；它替换派生向量缓存，不改信念文字与认识论状态。旧向量没有保留为第二套索引，若要回到旧嵌入模型，切回配置并重新重建。

## 8. Windows EXE 构建

已提供构建配方，但本轮没有下载打包依赖、构建或在干净机器运行 EXE。请在 Windows 项目根目录执行脚本中的命令，或按你已有的 PowerShell 脚本策略运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[packaging,documents]"
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm .\scripts\autodidact.spec
```

预期输出是 `dist\Autodidact\Autodidact.exe`，分发整个 `Autodidact` 文件夹，不能只复制 EXE。打包配置包含迁移、默认使命配置及 Playwright 驱动资源；Chromium 浏览器缓存不包含在包内。

双击程序默认启动本地工作台。首次启动把默认配置放在 `%LOCALAPPDATA%\Autodidact`，已有配置不会覆盖。在该目录编辑 `.env` 的数据库与模型参数。PostgreSQL/pgvector 和模型服务仍需自行准备，启动器不会自动安装数据库。
