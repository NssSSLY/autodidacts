# Autodidact 部署、安装、打包与验证手册

更新：2026-09-24。适用代码：`d3e8e96` / 功能基线 `d374b27`。主要操作环境为 **Windows PowerShell**，请分段执行；Linux 差异在第 10 节。路线与最终效果见[路线评估](路线评估与初始构想对照.md)。

## 1. 先选你要完成的事情

| 目的 | 需要什么 | 按本文执行 |
|---|---|---|
| 先确认代码和 Python 能工作 | Python 3.12、项目源码；首次安装需联网 | 第 3—4 节，不用数据库或模型密钥 |
| 验证数据库和迁移 | 再准备 PostgreSQL + pgvector；下文用 Docker | 第 5—6 节，不用真实模型密钥 |

推荐现在采用“Windows 本地 Python + Docker 中的数据库 + 模型 API”。不用购买服务器，也不用购买 GPU。Docker 在当前仓库只负责数据库；智能体 Python 进程运行在你的电脑上。

## 2. 环境清单与机器配置

### 2.1 必要与可选项

| 项目 | 要求与用途 |
|---|---|
| Python | 项目声明 `>=3.12`；为复现本地测试，先用 64 位 Python 3.12。其他版本需自行复测 |
| Git | 获取和更新仓库；只下载源码包时可省略克隆步骤 |
| Docker Desktop | Windows 上运行 PostgreSQL/pgvector 的便捷方式；使用 Linux 容器后端 |
| PostgreSQL/pgvector | 持久学习数据与语义检索；仓库镜像为 `pgvector/pgvector:pg16` |
| 真实模型服务 | 暴露 `/chat/completions` 兼容接口，支持按提示输出可解析 JSON；需要你自己的访问权限和额度 |
| 搜索 | 默认 DuckDuckGo HTML 后备；可选 Brave Search API 密钥；网络必须可访问对应服务 |
| 嵌入服务 | 可选，当前要求 1536 维；关闭时回退到最近信念检索 |
| Playwright Chromium | 仅试验网页模型适配器时需要下载浏览器；普通 API 学习流程不需要浏览器二进制 |

Windows 使用 Docker Desktop 前按其[官方安装要求](https://docs.docker.com/desktop/setup/install/windows-install/)准备受支持的系统、WSL 2、硬件虚拟化等。官方列出至少 8 GB 系统内存；本项目 API 模式可先按 **4 个逻辑 CPU、16 GB 内存、20 GB 可用磁盘**规划开发机，这是预留 Docker、依赖和数据空间的工程估算，未经项目负载测试，不是硬性最低配置。无需本地推理时不要求独立显卡。若另行部署本地大模型，其内存/显存需求取决于模型大小、量化与并发，需要单独评估。

官方参考：[Python 虚拟环境](https://docs.python.org/3.12/tutorial/venv.html)、[Docker WSL 后端](https://docs.docker.com/desktop/features/wsl/)、[pgvector 安装说明](https://github.com/pgvector/pgvector#installation)。服务器不使用 Docker Desktop，应安装对应系统的 Docker Engine/Compose 或自行管理 PostgreSQL。

## 3. 进入仓库，准备独立 Python 环境

你当前已有仓库，直接打开 PowerShell：

```powershell
Set-Location 'C:\file\project\autodidact_v0_1'
python --version
git --version
```

如果换到新电脑，先在你希望保存项目的父目录执行以下命令，然后始终留在新仓库根目录：

```powershell
git clone https://github.com/NssSSLY/autodidacts.git
Set-Location .\autodidacts
```

建立环境和安装开发依赖（已有环境会保留）：

```powershell
if (-not (Test-Path .\.venv\Scripts\python.exe)) { python -m venv .venv }
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.version)"
```

预期解释器路径指向项目 `.venv\Scripts\python.exe`；`pip check` 应报告依赖没有损坏。如果 `python --version` 不是目标版本，先选对解释器；装有 `py` 启动器时，可用 `py -3.12 -m venv .venv` 创建新环境。不要把已有环境目录直接复制到另一台电脑，目标机器重新创建即可。

本文直接调用虚拟环境解释器，不要求执行 `Activate.ps1`，也不需要修改 PowerShell 执行策略。`pytest` 来自安装参数 `.[dev]`，缺少它通常意味着用了另一套 Python 或漏装开发依赖。

## 5. 启动数据库，创建配置

### 5.1 Docker 就绪

从官方安装 Docker Desktop，完成要求的 WSL/虚拟化设置，启动桌面程序，选择 Linux 容器。重新打开 PowerShell，回到仓库根目录：

```powershell
docker version
docker compose version
```

`docker version` 应同时显示客户端和服务端信息。只有客户端或无法连接 daemon，说明 Docker 引擎尚未运行，先解决再继续。

### 5.2 首次配置

```powershell
if (-not (Test-Path .\.env)) { Copy-Item .\.env.example .\.env }
notepad .\.env
```

此时先保留 `LLM_PROVIDER=mock`；数据库示例配置为：

```dotenv
DATABASE_URL=postgresql+asyncpg://autodidact:autodidact@localhost:5432/autodidact
LLM_PROVIDER=mock
EMBEDDING_PROVIDER=disabled
```

已有 `.env` 不要覆盖；真实密钥放在该文件中，它已被 Git 忽略。系统环境变量可能覆盖 `.env`，如果修改不生效，检查是否给同名变量设过进程或系统值。

当前 Compose 默认使用演示账户密码和 `5432:5432` 端口映射。单机使用建议先在 `docker-compose.yml` 将这一行改为 `127.0.0.1:5432:5432`，仅本机可连接。服务器部署必须改成独立密码、限制访问，并同步修改 `DATABASE_URL`。容器已经初始化数据卷后，修改 `POSTGRES_PASSWORD` 变量不会自动改掉库内原密码，应通过数据库管理员正常修改角色密码。

```powershell
docker compose up -d postgres
docker compose ps
docker compose exec -T postgres pg_isready -U autodidact -d autodidact
```

预期服务变为 `healthy`，`pg_isready` 显示接受连接。如果刚启动尚未就绪，查看日志后再检查：

```powershell
docker compose logs --tail 60 postgres
```

### 5.3 初始化与检查持久状态

默认使命是研究无人机自主系统。若这是全新学习库，想换领域，可先编辑 `config/agent.yaml` 中的 `agent.mission` 和 `agent.initial_focus`，再执行：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli bootstrap
.\.venv\Scripts\python.exe -m autodidact.cli status
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT version_num FROM alembic_version;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c "SELECT extname FROM pg_extension WHERE extname = 'vector';"
```

当前迁移版本应是 `20260920_0003`，扩展列表包含 `vector`。新库 bootstrap 后应有智能体及种子目标，信念可以是 0。此步骤不需要真实 LLM 密钥。

修改 YAML 不会清除旧目标，也不保证更新已有同名 Agent 记录；当前库没有完整的多智能体隔离。试验不同使命时使用单独数据库，不要仅改名称后假设数据已隔离。`init-db` 会升级结构；有价值的已有库先按第 9 节备份。

若不用 Docker：准备 PostgreSQL 和 `vector` 扩展，创建专用角色及数据库，把 `DATABASE_URL` 指向它，再执行同样的 Python 初始化命令。SQL 检查通过你安装的 `psql` 或管理界面完成。


只在看到两个在线测试真实通过后，才能记录数据库验证成功。对于当前版本，单独运行应显示 `2 passed`，完整测试预计 `60 passed`，这是验收预期，不是本次已取得结果。

在线测试创建随机 schema，验证无版本 0001 旧结构升级后保留 Agent、并发 Claim 去重、pgvector 查询，最后删除自己创建的 schema。它要求库名以 `_test` 结尾，并有建 schema/扩展权限；不要把学习库地址放进这个变量。当前测试没有覆盖所有 Evidence/Dispute 并发、生产恢复和完整端到端流程，后续仍需增加。

## 7. 配置真实模型，启动第一次学习

### 7.1 修改 `.env`

```powershell
notepad .\.env
```

编辑对应条目，不要重复追加多个同名键。示例值必须替换成你的服务参数：

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://你的提供方地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=提供方实际支持的模型标识
LLM_TEMPERATURE=0.2
SEARCH_PROVIDER=auto
BRAVE_SEARCH_API_KEY=
EMBEDDING_PROVIDER=disabled
```

适配器在基础地址后拼接 `/chat/completions`，因此不要把完整接口路径填到 `LLM_BASE_URL`。服务还需返回兼容结构；网页聊天订阅本身不等于 API 权限。若模型服务不要求密钥，仍需满足当前适配器的非空配置校验，具体接入应遵循该本地服务文档。

可选：有 Brave Search API 访问权限时填写其密钥；没有则保留空值使用后备。网页模型目前不能只在配置中切换就成为主学习模型，相关集成尚未完成。

模型可能一次研究调用多次。先设置提供方账户的费用/额度上限并仅运行一次；项目当前的 `max_cycles` 不是令牌或费用上限。不要一开始就调成长期大循环。

### 7.2 可选语义召回

先让基础学习跑通，再按需启用：

```dotenv
EMBEDDING_PROVIDER=openai_compatible
EMBEDDING_BASE_URL=https://你的嵌入服务地址/v1
EMBEDDING_API_KEY=你的嵌入服务密钥
EMBEDDING_MODEL=实际输出1536维的模型标识
```

当前 `.env.example` 未列出这组字段，可自行添加。维度不匹配会失败并回退，不要为通过测试随意截断向量。已有无向量信念不会自动批量回填，更换嵌入模型还需要后续的版本与重建机制。

预期输出包含 `status`、`goal`、`score`、`sources`、`claims`、`beliefs_promoted`、`disputes_created` 和 `follow_up_goals`。正确运行不保证 `passed`：找到资料但证据不足、评估失败或主张冲突时，信念晋升数为 0 可能是正确保护行为。

## 8. 第三层验证：检查究竟学到了什么

以下查询均为只读，可以先查看最近目标与结论：

```powershell
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT title, status, retry_count FROM goals ORDER BY created_at DESC LIMIT 10;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT statement, source_ids FROM claims ORDER BY created_at DESC LIMIT 5;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT status, excerpt, reason FROM claim_evidence ORDER BY created_at DESC LIMIT 5;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT statement, status, source_count, test_score FROM beliefs ORDER BY created_at DESC LIMIT 5;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT status, resolution_notes FROM disputes ORDER BY created_at DESC LIMIT 5;'
docker compose exec -T postgres psql -U autodidact -d autodidact -c 'SELECT id, success, completed_at FROM learning_sessions ORDER BY created_at DESC LIMIT 5;'
```

人工抽查至少一条主张：沿来源 ID 找到原始 URL，确认摘录存在、上下文支持完整命题、来源不是同文转载。不要只看 LLM 给出的 `score` 或 `verified` 字样；当前评估器还不是独立闭卷考试。

第二次运行可验证旧记录是否保留、是否产生后续目标。确认费用和错误情况后，再尝试有限循环：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli run --max-cycles 3
```

`--max-cycles` 使用正整数。默认配置为每进程 20 轮、间隔 30 秒；`daily_goal_limit` 当前限制一次补充目标池的数量，不能当成严格每日预算。不要并行启动多个学习进程，当前目标领取和整个会话恢复还未完成并发执行验收。

真实模型配置后可体验示例基准：

```powershell
.\.venv\Scripts\python.exe -m autodidact.cli benchmark --path data/benchmark/sample.json
```

示例题公开、当前由模型辅助评分，且没有完整的带/不带记忆四组对照；这条命令不证明 30 天成长。Mock 模型没有该基准裁判的完整夹具，不要用 Mock 的失败判断真实基准功能。

## 9. 停止、备份、迁移与升级

### 9.1 停止与重新启动

让有限循环自然结束最容易检查；需中断时在前台按 `Ctrl+C`。当前部分中间状态不会自动恢复，下一次启动前检查 `goals` 和 `learning_sessions`，不要直接删除或批量重置它们。

```powershell
docker compose stop postgres
docker compose start postgres
```

这两条分别停止和启动数据库，不会移除命名卷。Python 进程停止后学习也停止；Docker 数据库在运行并不意味着智能体仍在研究。不要把 `docker compose down -v` 当日常停止命令，它会删除数据卷。

### 9.2 导出学习库

先结束学习进程，保持数据库运行。以下把二进制备份先写容器内再复制出来，避免 Windows PowerShell 文本重定向损坏文件：

```powershell
$backupDir = Join-Path $env:LOCALAPPDATA ('Autodidact\backups\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backupDir -Force | Out-Null
docker compose exec -T postgres pg_dump -U autodidact -d autodidact -Fc -f /tmp/autodidact-backup.dump
docker compose cp postgres:/tmp/autodidact-backup.dump "$backupDir\autodidact.dump"
Get-Item "$backupDir\autodidact.dump"
```

确认前一个命令成功后再执行下一个，并另存使命配置、代码提交号及依赖清单。`.env` 含密钥，应单独保管，不放进公共源码包。数据库备份可能包含研究资料与模型输出，也不应提交仓库。改过数据库账户/库名时，同步替换示例参数。

换机恢复时先安装环境，将备份放到新机器，使用新的空数据库验证恢复，避免覆盖原库：

```powershell
# 将下面路径替换为新机器上的实际备份文件
docker compose cp 'C:\你的备份路径\autodidact.dump' postgres:/tmp/autodidact-restore.dump
docker compose exec -T postgres createdb -U autodidact autodidact_restore
docker compose exec -T postgres pg_restore -U autodidact -d autodidact_restore --no-owner /tmp/autodidact-restore.dump
```

恢复库验证通过后，把 `.env` 的库名改为 `autodidact_restore`，执行 `init-db` 和 `status` 检查迁移版本、目标、信念和历史。若新库名已存在，先确认用途并选择另一个空库，不要为了执行示例而删除它。

### 9.3 更新程序

备份完成、学习进程已停止且工作区修改已妥善保存后：

```powershell
git status --short
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m autodidact.cli init-db
.\.venv\Scripts\python.exe -m autodidact.cli status
```

有未提交改动或分支冲突时先处理，不强制覆盖。Alembic 降级会删除某些新增字段/表的数据；回退程序前需评估数据库兼容性，不能只回退 Git 代码后继续写同一库。

## 10. 放到 Linux 服务器是否必要

你现在可以在本机完成验证。服务器主要解决电脑关机后不能继续运行的问题，不会自动增加模型推理能力。使用 API、小规模单进程研究时，可从约 **2 vCPU、4 GB 内存、20 GB 以上磁盘**做容量试验；这是未压测的起步估算，启用浏览器、并发或本地模型需重新规划。

服务器先准备 Git、Python 3.12、venv、Docker Engine 与 Compose 插件；系统安装命令依发行版而异，按对应官方安装说明完成。以下为运行步骤模板，本次未在 Linux 实机演练：

```bash
git clone https://github.com/NssSSLY/autodidacts.git
cd autodidacts
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
test -f .env || cp .env.example .env

.venv/bin/python -m autodidact.cli init-db
.venv/bin/python -m autodidact.cli bootstrap
.venv/bin/python -m autodidact.cli run --max-cycles 3
```

先完成有人观察的运行和备份演练，再接服务管理/调度。当前还缺跨进程预算、检查点恢复、完整告警和互斥领取目标；简单设置“进程失败无限重启”可能重复调用模型或留下更多中间状态。当前也没有对外 Web 端口，不需要为了使用 CLI 开放网站端口。

## 11. 打包安装应该怎么做

### 11.1 今天可用：源码交付包

最稳妥的迁移方式是 Git 克隆或源码 ZIP，在目标电脑创建 `.venv`，按本文安装；有学习数据时另行备份恢复。若需要给别人一个源码包，在已提交所需文件后执行：

```powershell
$releaseDir = Join-Path $env:TEMP ('autodidact-release-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $releaseDir | Out-Null
git archive --format=zip --output="$releaseDir\autodidact-source.zip" HEAD
Get-Item "$releaseDir\autodidact-source.zip"
```

`git archive` 只打包当前提交中受版本管理的内容，不包含未提交文件、`.env`、`.venv`、数据库卷和浏览器登录资料。解压后进入项目根目录，从第 3 节的创建虚拟环境开始。数据库与密钥分别配置。

项目有 Python 包构建元数据，但当前迁移代码通过 `__file__` 向上寻找仓库根目录的 `alembic.ini` 和 `migrations/`，配置也依赖工作目录。只发一个 wheel 或把 `pip install` 当完整安装包，会遗漏这些运行资源；目前应保留完整源码目录并用可编辑安装。

### 11.2 EXE 可做，但当前没有可交付的构建配方

后续可使用 PyInstaller 打包 Python 程序。它能携带解释器和依赖，额外配置/迁移数据文件需要明确打包；构建产物依赖目标操作系统，Windows 产物应在 Windows 上构建验证。[PyInstaller 官方说明](https://pyinstaller.org/en/stable/operating-mode.html)

项目真正交付 EXE 前至少要完成：迁移资源定位和可写配置目录、依赖动态导入检查、CLI 入口包装、数据库连接引导、日志与升级/回退、无开发环境机器上的干净安装验收。浏览器模型还涉及浏览器二进制和用户登录目录的独立管理。

所以目前不提供一条未经验证的 `pyinstaller --onefile` 命令冒充可用安装器。即使 EXE 成功，PostgreSQL/pgvector、模型服务和网络仍需提供；数据库不能因此被替换或自动消失。后续交付优先考虑“文件夹式程序包 + 配置向导”，验收通过后再封装安装器。

### 11.3 如果想通过浏览器与它对话

这是另外一个产品入口，需要任务/问答 API、前端、会话与鉴权，以及读取 Belief/Evidence/Dispute 的回答服务。网页应显示来源、条件和未解决争议，提交学习目标而非绕过证据门槛写信念。当前 `web_models/` 是“程序去咨询别的网站模型”的适配器，尚不提供这个用户界面。

## 12. 常见问题速查

| 现象 | 优先检查 |
|---|---|
| `No module named pytest` | 用本文 `.venv` 的 Python，重新安装 `.[dev]` |
| `autodidact` 命令找不到 | 用 `.venv\Scripts\python.exe -m autodidact.cli ...`，确认已安装项目 |
| 找不到 `config/agent.yaml` / `alembic.ini` | 回到完整源码根目录运行；目前不支持随便移动资源或只安装 wheel |
| `docker` 不存在 / daemon 不可达 | 安装并启动 Docker Desktop，确认 Linux 容器、WSL 和服务端就绪 |
| 数据库连接拒绝 / 5432 占用 | 看 `docker compose ps`、日志与 `.env`；若改宿主机端口，同步改 URL 和测试变量 |
| 密码已改但认证失败 | `.env` 与库内角色密码是否一致；改容器环境变量不会替旧数据卷改密码 |
| `vector` 扩展不可用 | 是否使用含 pgvector 的镜像/数据库安装，是否有建扩展权限 |
| 2 项数据库测试跳过 | 未设置 `AUTODIDACT_TEST_DATABASE_URL`；跳过并非通过 |
| `401` / `403` / `404` / `429` | 密钥、模型权限、接口基础地址、余额与限流；不要反复大循环重试 |
| 模型 JSON 解析失败 | 提供方/模型是否遵循结构化输出；保留错误样本交给开发者处理 |
| `no readable sources` | 搜索网络、可读内容类型、站点限制；当前 WebReader 不直接读取 PDF |
| 运行结束但信念为 0 | 看是否 Mock、无支持来源、有争议或评估失败；不应为得到数量而降低证据标准 |
| 下次没有继续中断的任务 | 当前未完整恢复 `PLANNED/RESEARCHING/...` 阶段；先查库，不直接清空任务 |
| 费用比想象高 | 一条 Claim 可能需多个支持判断和最多 40 个候选信念比较；先一轮观察再设额度 |
